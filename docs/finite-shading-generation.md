# 探索で見つかった小盤面を、出題できる完成解から生成する

`generate_shading.py generate --selection finite` は、選んだヒント形式で一意にできる
完成解を先に全列挙から選び、既存の生成器でヒントを削減します。
対応する[黒白の組み込みルール](shading-fragments.md)と[固定部屋のルール](room-fragments.md)・9セル以下・8ルール出現以下に限定した、任意指定の生成方法です。
通常の `--selection solver` が既定で、以前の生成方法・出力は変わりません。

## 完成解を選ぶ理由

基礎ルールを満たす完成解でも、選んだヒント形式だけで一意にできるとは限りません。
例えば2×3の「黒3個＋白連結」は64配置のうち10完成解がルールを満たし、
行の個数だけで一意になるのは `.../###` と `###/...` の2つです。
通常生成はその2つ以外を選ぶと、全候補ヒントの一意性検査で失敗します。
有限選択は、既存の小盤面診断と同じ意味で識別できる候補へ直接つなぎます。

## 選定から解いてみるまで

リポジトリのルートで `uv sync --all-packages --group dev --locked` を実行してから試します。
この例では**黒数と白連結の2規則**を選びます。候補番号は1始まりです。

```sh
uv run --no-sync python examples/explore_shading.py --rows 2 --cols 3 --black-counts 3 --candidates count connected-white --hints row-count --explain 1 2 --export-recipe chosen.json
uv run --no-sync python examples/generate_shading.py generate --recipe chosen.json --selection finite --seed 0 --output puzzle.json --quiet
uv run --no-sync python examples/generate_shading.py show puzzle.json
uv run --no-sync python examples/generate_shading.py verify puzzle.json
```

`show` は答えを隠してルール・行ヒント・`???/???` の入力テンプレートを表示します。
`?` を黒 `#` または白 `.` に置き換え、`check puzzle.json --answer "各行を/で区切る"` で確認できます。
探索レポートには反例の答えが含まれます。生成物もJSON内には答えを保持するため、遊ぶときは `show` を使ってください。

Python 3.12.14 / OR-Tools 9.15.6755 / Windows では seed 0で、表示上の2行目の黒数0というヒント1個になります。
唯一解・既約性を確認した後、ルールの寄与も調べられます。この診断は答えと別解を表示します。

```sh
uv run --no-sync python examples/diagnose_shading_rules.py puzzle.json
```

同じ残ったヒントで黒数ルールを外すと8解、白連結を外すと1解です。
出題に使えることは、全ルールが最終問題に必要であることや、人間にとって面白いことを意味しません。

## 選択と検証を分ける

1. 既存の独立チェッカーで最大512配置を列挙し、基礎ルールを満たす完成解を得ます。
2. 選択済みの候補ヒントを完成解ごとに抽出し、同じヒントを持つ完成解が1つだけの候補を残します。
3. 座標順のビット列で整列し、seed付きのPython乱数で1候補を選びます。
4. 同じレシピのDSLで全候補ヒントから唯一解を証明し、選択した盤面・抽出ヒントと照合します。
5. 既存の `reduce_clues` でヒントを削減します。選択用の盤面固定制約を残して一意と認定することはありません。

完成解がない場合と、完成解はあるがどれも選択ヒントで一意にならない場合を区別して失敗します。
後者はseedだけでは改善できません。例えば2×2の「黒2個＋非隣接」は、行・列の個数だけでは対角2解を区別できません。
未知のルール、サブクラス、範囲外のサイズ・seedは拒否します。列挙とDSLが一致しなければ保存しません。
実行時のDSL照合は選んだ候補について行います。全候補を毎回DSLで再列挙する処理ではありません。

ルール、盤面、候補ヒント形式・順序は変更しません。セルヒントを勝手に追加しません。
出力は既存の `shading-v1` / `shading-v2` のままで、`show`、`check`、`verify`、保存問題診断を使えます。
追加の選択方法は実行条件として `environment.completion_selection = "finite-identifiable-v1"` に記録します。
メタデータは検証の根拠ではなく、保存したヒントと答えそのものを検証します。
再生成には同じレシピ・seed・`--selection finite`・依存環境を使ってください。

## 範囲と検証

25セルまでの通常生成は維持しますが、finite指定は9セルを超えると失敗し、自動で別方式に切り替えません。
最大512配置×8ルールの有限選択に加え、DSL求解とヒント削減が必要です。全処理の時間上限はありません。
同じ環境での再現性をテストします。異なるOS・Python・OR-Toolsでの同一出力、seedを変えた際の必ず異なる答え、
対称性を除いた抽選、最少ヒント数、人間の難易度は保証しません。

テストでは独立したDSL全解列挙で候補集合を照合し、10解中2候補の回帰例、同じヒントでの唯一解・既約性、
解・ヒントの照合失敗、不成立とヒント不足、入力境界、失敗時の出力保持を確認します。
探索CLIで保存した実ファイルを生成・表示・正誤確認・検証・診断へ渡す流れと、別プロセスでの再現性も検証します。

異種パズルへの同様の選択、探索結果のランキング、任意DSLの生成方針には一般化していません。

[複数 seed の比較](compare-shading-seeds.md)では、保存済みレシピから生成した問題について、
削減後のヒントに対するルールの必要性を比べ、１問を選んで保存できます。
