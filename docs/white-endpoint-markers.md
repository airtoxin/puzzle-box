# 丸の位置を白い端点と一致させる

`WhiteEndpointMarkers(markers)` は、丸のあるマスを白にし、その上下左右の白い隣接マスをちょうど1個にします。
丸のない白マスが隣接白1個になることも禁止します。白の端点と丸の位置が一致する条件です。
[ぬりみさきの公式ルール](https://www.nikoli.co.jp/ja/puzzles/nurimisaki/)の、数字のない丸の条件を切り出しています。
この断片自体は直線長を指定しません。[数字付きの丸](numbered-white-endpoints.md)は、既存の可視数ルールと組み合わせて表せます。
白の連結と黒白の2×2禁止は別の既存ルールで加えます。

| 入力 | 意味 |
| --- | --- |
| `1` | 数字なしの丸。白で、上下左右の白い隣がちょうど1個 |
| `0` | 丸なし。白の場合は端点になれない。黒でもよい |

1は丸の存在を表す符号で、盤面に数字1を表示する意味ではありません。0も数字のヒントではありません。
孤立した白マスは白い隣が0個なので端点ではなく、丸なしの場所には置けます。
1×1に丸を置くと解なしです。盤面の外を白として数えることはありません。
全マス0でも何も制限しないわけではなく、「白の端点が0個」という条件が残ります。

この断片だけでは、白全体の連結、枝分かれ・輪の禁止、白の存在を要求しません。
3つの端点を持つT字や、端点を持たない輪も、それぞれの丸配置で成立します。
[端点数](cell-path-fragments.md)と違い、同じ数の端点でも場所が異なれば解とは認めません。

## 数字なしの丸で生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-nurimisaki-recipe.json --selection finite --seed 0 --output nurimisaki.json --quiet
uv run --no-sync python examples/generate_shading.py show nurimisaki.json
uv run --no-sync python examples/generate_shading.py verify nurimisaki.json
```

[2×3の例](../examples/shading-nurimisaki-recipe.json)は、左上と右下に丸を固定し、白の連結・黒白それぞれの2×2禁止を組み合わせます。

```text
1 0 0
0 0 1
```

このルール配置には3解があり、生成器は一意性に必要なセルヒントを残します。
どの完成盤面を選ぶかによって残るセルヒントは異なり、固定された丸だけで一意だとは扱いません。
丸の位置はルールの一部です。生成器は丸を選択・削減せず、黒白のセルヒントを削減します。
丸を消すと、その場所に端点が置けなくなるため、単に制約を緩める操作にはなりません。
`show` は丸の格子を `o`、丸なしを `.` として別に示し、丸のマスは既知の白として表示します。
テンプレートを黒 `#`・白 `.` で埋め、`check nurimisaki.json --answer "行/行"` に渡すと確認できます。
表示時に完全解は隠しますが、保存JSON自体には答えが入っています。

```python
from puzzle_defs import ConnectedWhite, NoBlack2x2, NoWhite2x2, ShadingRecipe, WhiteEndpointMarkers

recipe = ShadingRecipe(2, 3, (
    WhiteEndpointMarkers(((1, 0, 0), (0, 0, 1))),
    ConnectedWhite(), NoWhite2x2(), NoBlack2x2(),
))
```

## 宣言型UIと保存形式

Webでは「丸を白の端点と一致させる」を選びます。初期選択の黒マス数は、不要なら外します。
入力は `markers/marker-grid`、表示は `endpoint-markers/cell-endpoint-markers` です。
新しい `marker-grid` は厳密な整数0/1だけの長方形格子で、一般の0〜99の数格子や、`null` を許すヒント格子とは区別します。
入力欄の0/1、サーバーのルール構築、表示計画を同じ意味で検証します。

丸はマス全体を囲む大きな円で表し、白として固定します。読み上げにも「白の端点の丸」を含めます。
固定ラベル・白の可視数・白成分の面積などを重ねても、それぞれの入力と意味を別に保ちます。
可視数の小さな丸数字とは大きさと凡例で区別します。表示できても、ルール同士が矛盾しない保証にはなりません。
マーカーの欠落・変更・要求していない格子を持つ表示計画は、ブラウザで拒否します。

保存IDは `white-endpoint-markers`、フィールドは `markers` だけです。
JSONは盤面と同寸の配列の配列を必須とし、空・不揃い・真偽値・小数・`null`・2以上・負数・未知フィールドを拒否します。
Python側では格子を不変のコピーにします。ファイル/UIで複数出現させる場合は、同じ格子を共有する必要があります。
正確な組み込み型だけを保存し、データから任意コードは実行しません。新IDやUI宣言を知らない旧版は拒否します。
既存の数格子とルールの意味は変えません。黒白以外のWebプロファイルへこのIDを渡すことはできません。

## 検証と限界

DSLは各マスの白い隣接数を整数変数で表し、丸の場所では白かつ隣接数1を強制します。
丸なしの場所では、隣接白1ならそのマスは黒でなければならないと制約します。補助の次数は見える回答に含めません。
テストは2×3の全64マーカー配置について、全64黒白盤面の端点位置を独立に求め、有限検査器とDSLの全回答を照合します。
別の参照実装は白マス対の距離から次数を数え、実装の近傍走査と分けます。
孤立白、空、T字、輪、端のマス、同数で位置だけ違う丸、補助変数に依存しない一意性、保存・表示・解答確認も対象です。

保存CLIは既存の25セル上限、Web・有限診断は9セル上限です。Webは既存の計算予算を使い、通常CLIには壁時計の上限がありません。
検証した小盤面から任意サイズの性能は保証しません。説明可能な推論手順は未対応と報告し、一意性を人間の解きやすさとは扱いません。
