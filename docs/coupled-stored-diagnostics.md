# 保存済みの異種合成パズルでルールの寄与を調べる

`diagnose_coupled_rules.py` は、実際に残ったヒントを固定してルールを1つずつ外し、
黒白セルとループ辺の両方を区別した解数・別解を表示します。
同じ保存解から作った全候補ヒントでも比較するため、削減前には不要でも出題後には必要なルールが分かります。
入力ファイルやヒントを変更する機能ではありません。レポートには答えと別解が含まれます。

## 最短の例

```sh
uv run --no-sync python examples/diagnose_coupled_rules.py examples/coupled-stored-sample.json --verify-models
uv run --no-sync python examples/diagnose_coupled_rules.py examples/coupled-stored-sample.json --json --output rule-report.json
```

保存例は2×4・矢印なしで、結合＋黒非隣接の2規則を使い、`(0,2)-(1,2)` の辺を使わないという
1ヒントだけを残しています。唯一解は全白の外周ループです。

| 外すルール | 元の答えの全18候補ヒントを固定 | 保存された1ヒントを固定 |
| --- | ---: | ---: |
| 結合（白セルと辺の連動） | 1解 | 123解 |
| 黒マス非隣接 | 1解 | 3解 |

結合を外すと白セルを通らない小さなループも許され、非隣接を外すと隣り合う黒マスも許されます。
ASCII図とJSONの反例は、外した規則以外と**同じ元のヒント**を満たします。
別解からヒント値を取り直す比較ではありません。

既存のヤジリン生成器の保存ファイルも、8セル以下ならそのまま入力できます。

```sh
uv run --no-sync python examples/generate_yajilin.py generate --rows 2 --cols 4 --arrow 0 0 right --seed 6 --output small-yajilin.json --quiet
uv run --no-sync python examples/diagnose_coupled_rules.py small-yajilin.json --verify-models
```

通常のヤジリンでは3規則をすべて有効として扱います。元の生成器の既定例は12セルなので、
この全列挙診断にはそのまま渡せません。生成成功や再試行の記録だけを信頼せず、入力問題を再検証します。

## 入力形式

既存の `puzzle-box/yajilin-v1` と、例示用の `puzzle-box/coupled-puzzle-v1` を受け付けます。
後者はヤジリンと同じ `rows`、`cols`、`arrow_sites`、`clue_kinds`、`clues`、`solution` に
必須の整数 `rule_mask` を追加した形式です。JSONのデータであり、Python式やクラスを実行しません。

| bit | 有効になるルール |
| --- | --- |
| 1 | 結合: 各通常セルの辺次数＋2×黒状態＝2 |
| 2 | 黒セルの縦横非隣接 |
| 4 | 辺集合が単一サイクル |

0〜7の整数を使います。全構成で固定なのは矢印障害物、非空の辺集合、次数0または2という条件です。
mask 0〜6は通常のヤジリンではありません。ヤジリン形式に `rule_mask` を混ぜて規則を変える入力は拒否します。
この変更は規則構成の生成器・ヒント削減器・探索結果の保存操作を追加しません。
例のファイルを編集する場合も、保存問題の一意性と保存解の一致が必要です。

- 縦横2以上、積8以下。2×2・2×3・3×2・2×4・4×2が対象です。
- 矢印位置は最大8、黒セルの解は最大8、辺の解は最大10。座標・方向・重複・範囲を検証します。
- ヒント形式は `arrow` / `black` / `edge` の重複なし配列。保存ヒントは最大32出現で、選択形式に限ります。
- 矢印ヒントは設定された位置と射線の長さ、黒ヒントは通常セル、辺ヒントは盤面内の隣接セル中心を参照します。
- 黒白が同じでも異なるループがあれば一意としません。不成立・非一意・保存解との不一致はエラーです。
- 冗長なヒントを含む一意な保存問題も診断できます。削除可能なヒント番号は1始まりで、重複も別の出現です。
  同じヒント2個は個別には削除可能でも、両方を消すと非一意になる場合があります。
- UTF-8のJSON、最大65,536バイト。未知の項目・形式、不正な型、重複キー、NaN / Infinityを拒否します。
- `seed`、`environment`、`generation` は任意の記録です。seedと再試行履歴の整合は検査しますが、
  環境情報の出所は認証しません。診断でseedを再実行することもありません。

`--output` はJSONレポートを保存します。入力と同じパス・シンボリックリンク・ハードリンクへの上書きは拒否します。
診断・モデル照合が失敗した場合は既存の出力を変更しません。正常終了は0、入力・検証エラーは2です。

## 比較・独立検証・計算量

JSON形式は `puzzle-box/coupled-stored-rule-analysis-v1` です。`stored_clues` と `full_candidate_clues` を区別し、
各 `removals` に両方での解数・必要性・別解を記録します。`comparison_is_for_stored_answer_only` は常に真です。
全候補ヒントは、選んだ `clue_kinds` だけを保存解から抽出し、未選択の形式を勝手に追加しません。

既定では座標・次数・連結成分による独立列挙器で有限集合を厳密に比較します。
`--verify-models` は元の問題、各ヒント1出現の削除、各ルール削除後の保存／全候補ヒントについて、
別に構築したDSL/CP-SATモデルの全解集合と照合します。補助的な回路の向きは同じ答えにまとめます。
求解未完了や集合の不一致なら検証済みレポートを返さずエラーにします。フラグなしは `models_verified=false` と明記します。

最大1,024辺部分集合を調べ、次数などを満たすものと最大256黒白配置を組み合わせます。
2×4矢印なしの基礎集合は1,792解です。最大32ヒント出現・3規則を別々に外すため、
モデル照合は最大39問い合わせ。同じ規則・ヒント集合は再利用します。
照合1問い合わせの既定上限は10秒ですが、全処理の壁時計時間の上限ではありません。
大盤面、任意DSL、全矢印配置を網羅した検証には広げていません。

テストは123解／3解の反例、全8規則構成、5種類の対応盤面形状、4方向の矢印、0ヒント、黒白だけの誤った射影、
重複・矛盾ヒント、保存解の改変、不正入力、時間切れ、CLI再現性と上書き防止を含みます。
辺ヒントだけを選ぶと、結合を外した全候補ヒントでの解数は41になり、保存1ヒントでは123です。
未選択の黒白ヒントを勝手に補わないこともモデルと照合しています。
個別に不要な規則を一括削除したり、ルールとヒントの同時最小化、最少ヒント数、別盤面での冗長性や難易度を主張したりしません。

[異種探索](coupled-rule-exploration.md)の列挙器・モデルと、ヤジリンの回答型・ヒント型・DSLを再利用します。
[黒白の保存ヒント診断](stored-clue-rule-diagnostics.md)と同じ比較方法ですが、回答は黒白と辺の両方です。
