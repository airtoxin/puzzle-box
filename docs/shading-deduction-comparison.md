# 生成候補の限定推論を比較する

[`compare_shading_deductions.py`](../examples/compare_shading_deductions.py) は、生成済みの
黒白問題を1〜8個読み、[説明付き推論](shading-deductions.md)だけでどこまで進むかを並べます。
候補ごとに唯一解・保存解との一致・ヒントの既約性を検証し、検証済みの問題に限定推論を適用します。
生成器・ルール・ヒントを変更せず、候補の自動選別や難易度評価もしません。

## 同じレシピで進み方が異なる例

リポジトリのルートで実行します。最初の例は未解決セルが残るため、終了コードは1です。

```sh
uv sync --all-packages --group dev --locked
uv run --no-sync python examples/compare_shading_deductions.py examples/shading-deduction-candidate-stalled.json examples/shading-connector-sample.json --phase-seconds 15 --total-seconds 30
```

両方とも2×3、白連結（非空）と白2×2禁止、セルヒントという同じレシピから生成した固定例です。
直接与えられたセル数が同じでも、実装済みの手法で進む範囲が異なります。

| 例 | ヒント数 | 直接の与件セル | 推論で確定するセル | 未解決セル | 状態 |
| --- | --- | --- | --- | --- | --- |
| `shading-deduction-candidate-stalled.json` | 4 | 4 | 1 | 1 | `stalled` |
| `shading-connector-sample.json` | 4 | 4 | 2 | 0 | `solved` |

最初の例では右側の2×2に白が3個あるため、座標 `(0,1)` を黒にできます。
残る `(0,0)` を白にすると孤立しますが、孤立領域を黒にする推論は未実装なので、そこは未知のままです。
唯一解の検証で得た答えを使って埋めません。次の例は既知の白同士をつなぐ通路の推論で完了します。
この違いは「実装した手順で完了するか」を表し、人間にとっての難しさの順序ではありません。

新しい候補を作る場合は、既存の生成コマンドで保存した `shading-v1/v2` を渡します。
上の例と同じ生成条件は次のとおりです。**生成コマンドにはこの比較CLIの時間予算は適用されません。**
出力先には新しい名前を指定してください。

```sh
uv run --no-sync python examples/generate_shading.py generate --rows 2 --cols 3 --rules connected-white no-white-2x2 --hints cell --selection finite --seed 0 --output candidate-0.json --quiet
uv run --no-sync python examples/generate_shading.py generate --rows 2 --cols 3 --rules connected-white no-white-2x2 --hints cell --selection finite --seed 2 --output candidate-2.json --quiet
uv run --no-sync python examples/compare_shading_deductions.py candidate-0.json candidate-2.json --phase-seconds 15 --total-seconds 30
```

生成側で時間予算を設けて保存した問題も、そのまま入力できます。このCLIは保存済み候補の比較専用で、
生成側のseed・試行数・予算を変更しません。生成と推論の両方を制限する場合は、それぞれに予算を設けます。
固定例の結果は生成環境に依存せず確認できますが、seedからの再生成はPython・OR-Tools・生成実装の変更を
跨いで同じ問題になる保証はありません。

## 出力の意味

通常表示はセルの値や答えを出さず、入力順の比較表を表示します。ソートや点数付けはしません。
`--json` では各問題の推論手順も出力するため、**推論で判明した答えが見えます**。
未解決のセルは未知のままです。個別の根拠を読むには `explain_shading.py FILE` も使えます。

- `Clues` は残ったヒントの数、`Given cells` はセルヒントが直接指定するマスの数です。
  行・列の個数ヒントは直接の与件セルに数えず、そこから確定したマスを `Inferred cells` に数えます。
- 有効な推論結果では「与件セル＋推論で確定したセル＋未解決セル＝盤面のセル数」です。
  手順数は1回に1セルを確定する現在の実装に依存し、人間の推論回数ではありません。
- `Group` はサイズ・順序付きのルール・候補ヒント形式が同じレシピの番号です。
  残ったヒントやseedは含みません。異なるレシピの論理的同値性は調べません。
- JSONには元の入力バイト列のSHA-256、推論器のソースSHA-256、Python/OR-Toolsのバージョンも記録します。
  元ファイルを変更せず、64KiB以内のスナップショットを検証と推論の両方に使います。

| 状態 | 意味 |
| --- | --- |
| `solved` | 唯一解・既約性を検証済み。実装した推論で全セルが確定した |
| `stalled` | 同じ検証を通過したが、実装した推論では未知セルが残った。推測で補完していない |
| `timeout` | 検証・推論のプロセスを打ち切った。未完の推論を結果として利用しない |
| `not_started` | 全体予算が残っておらず、処理を開始しなかった |
| `rejected` | 入力が範囲外、不正、唯一解や既約性の検証に失敗したなど。理由を併記する |
| `error` | workerの起動失敗、不正な応答、検証後の推論矛盾や保存解との不一致などの内部エラー。推論結果として扱わない |

非対応形式や一つの候補の失敗があっても、残り時間があれば次の候補へ進みます。
workerの入力検証失敗（終了コード2）と内部エラー（終了コード3）は別に記録します。
終了コードは全候補が `solved` なら0、それ以外の状態を含むと1、不正なCLI引数や実行全体のI/Oエラーは2です。
`rules_without_deductions` が空でも、対応ルール型について全ての推論を実装している意味ではありません。
孤立領域の黒確定、非空条件だけからの推論、仮定・場合分け、その他の未実装手法は使いません。

## 範囲と計算予算

入力は黒白 `shading-v1/v2`、各9セル・8ルール・32ヒントまで、1ファイル64KiBまでです。
Slitherlink・ヤジリン・任意の独自ルールは対象外で、範囲外の入力を `stalled` として報告しません。

既定の予算は候補ごとのworkerが15秒、比較全体が120秒です。有限の正数で、最大はそれぞれ300秒と3600秒です。
各workerには「候補の予算」と「全体の残り時間」の小さい方を渡し、検証だけで使い切っても
推論用に予算をリセットしません。Python起動・import・唯一解と既約性の検証・推論を同じworkerで行います。
全体予算は入力スナップショットや一時ファイル処理も含みますが、環境情報の取得は測定前です。

workerは別プロセスを起動せず、タイムアウト時は終了・回収します。OSのプロセス起動・終了待ちや
ファイル処理、時間分解能によって実際の終了は予算を超える場合があります。CPU・メモリの隔離ではありません。
外部からコマンドを中断した場合のチェックポイント保存はありません。
時間切れや未実行を除いて「解けた割合」を高く見せないでください。少数の候補から他のseedや人間の難易度へ
一般化せず、今回だけの比較結果や測定記録はPRまたはissueへ残してください。
