# 黒白セルとループを組み替えて比べる

既存のヤジリン合成例から3つの規則を取り出し、その有無とヒント形式を小盤面で比較する実験です。
「黒セルの答えが同じなら唯一解か」「辺ヒントだけで足りるか」「どの規則の組が矛盾するか」を、具体的な盤面で確認できます。
任意の DSL 制約を探索する汎用システムではありません。

```sh
uv sync --all-packages --group dev --locked
uv run --no-sync python examples/explore_coupled.py --verify-models --explain 3 --hints black
uv run --no-sync python examples/explore_coupled.py --arrow 0 1 down --verify-models --explain 3 --hints arrow
uv run --no-sync python examples/explore_coupled.py --explain 7 --hints
uv run --no-sync python examples/explore_coupled.py --json > coupled-report.json
```

最初のコマンドは [射影の反例](../examples/coupled-projection-sample.txt)、
2番目は [成立しない組合せ](../examples/coupled-conflict-sample.txt) を再現します。
JSON はこの実験の比較レポートで、`generate_yajilin.py` が読み込むパズル形式ではありません。
入力ファイル、任意コード、式の文字列評価は使いません。

## 比較する規則とヒント

各辺はセル中心を結びます。矢印セルは黒にもループにも使えず、配置と方向は全構成で固定です。
さらに「辺は非空」「各普通セルの次数は0または2」を常に課します。
この土台に、次の3規則の全8部分集合を重ねます。

| マスクのビット | 規則 | 意味 |
| --- | --- | --- |
| 1 | `coupling` | 各普通セルで `degree + 2 * black == 2`。黒は次数0、白は次数2 |
| 2 | `non_touching` | 黒セル同士は辺で隣接しない |
| 4 | `single_cycle` | 使用辺は単一のサイクル |

マスク7は非空ループを要求する既存 `YajilinRecipe` に対応します。
0〜6は規則を外した実験です。例えば結合を外すと黒セル上にも辺を引け、
単一サイクルを外すと離れた複数ループが許されます。通常のヤジリンとして出題してはいけません。
既存 `YajilinPuzzle` / `YajilinRecipe` や `single_cycle` の空ループ仕様は変更していません。

ヒントは `ArrowCountClue`（A）、`BlackCellClue`（B）、`EdgeStateClue`（E）を再利用し、
なし・A・B・AB・E・AE・BE・ABE の8方針を比較します。選んだ種類の**全候補ヒント**を使います。
矢印がなければ A はヒントを一つも追加しません。矢印数だけを外してもセルは障害物として残ります。
`--hints` は `--explain` の詳細表示対象を選ぶだけで、比較自体は常に全8方針です。

表の `unique/total` は「唯一の黒セル＋辺集合を定めるヒント組の数 / 異なるヒント組の数」です。
同じヒント組を持つ全解を一つのグループとします。確率や難易度ではありません。
ヒント削減後の寄与は調べておらず、[黒白の保存ヒント診断](stored-clue-rule-diagnostics.md)とも区別します。

## 2×4の再現結果

矢印なしの全解数は次のとおりです。独立した有限列挙と各 DSL モデルの射影解集合を照合しました。

| マスク | 規則 | 黒セル＋辺の解数 |
| --- | --- | ---: |
| 0 | 追加規則なし | 1792 |
| 1 | 結合 | 7 |
| 2 | 非隣接 | 287 |
| 3 | 結合・非隣接 | 2 |
| 4 | 単一サイクル | 1536 |
| 5 | 結合・単一サイクル | 6 |
| 6 | 非隣接・単一サイクル | 246 |
| 7 | 3規則すべて | 1 |

マスク3は全白のセル配置だけが可能ですが、外周1ループと離れた2つの四角形があります。
黒セルだけに射影すれば一意という誤判定になります。完全な黒セルヒントでも2解のままで、
辺ヒントを加えると区別できます。CLI は同じヒントを満たす2枚の答えを描きます。

結合を外したマスク0では、完全な辺ヒントでも黒セルが決まりません。
黒セルと辺の両方を与えれば1792組すべてが一意になります。結合ありのマスク1では辺ヒントだけで7組すべて一意です。
これが、異種の答えを相互制約でつなぐことの具体的な効果です。

マスク7ではヒントなしでも一意です。どの規則を1つ外しても複数解になります。
一方、完全な黒セル＋辺ヒントを固定すれば、どの規則を外してもその解は一意のままです。
レポートの `unique_groups_lost_if_removed` は、同じ全候補ヒントを保って規則だけを1つ外したときに
唯一性を失うグループ数です。`removals` はヒントなしの解集合の増分と追加解の例を示します。

`--arrow 0 1 down` では、結合だけなら1解、非隣接だけなら31解ありますが、
両方を課すマスク3は0解です。この配置では、矢印を避けるループの外側のセルを黒にすると黒同士が接触します。
各規則を外したときの成立例を表示します。ヒントの追加だけではこの矛盾を救えません。
2×2に矢印セルを1つ置いた場合は、任意規則を加える前の土台自体が不成立です。

## 検証方法と上限

- 縦横は2以上、積は8以下です。2×2、2×3、3×2、2×4、4×2を扱えます。3×3以上は拒否します。
- 最大10辺の1024部分集合を直接調べ、非空・次数・障害物の条件で絞ります。2×4の7つの辺集合と
  256通りの黒セル配置から1792の土台の答えが得られます。その後に8規則構成・8ヒント方針を比較します。
- `coupled_oracle.py` は CP-SAT や DSL 制約を呼ばず、座標・集合・次数・連結成分を計算します。
  矢印数も `recipe.ray()` を使わず幾何的に数え、既存レシピの抽出結果とテストで照合します。
- `--verify-models` は別に組み立てた DSL モデルを CP-SAT で全列挙し、黒セルと辺の組へ射影して比較します。
  内部の向きの違いを重複除去します。例のマスク7は内部代入2通りでも見える答えは1つです。
  この診断に限り低レベルモデルを参照し、ライブラリの API を増やしていません。
- 各モデルの検証上限は10秒です。時間切れなどで全列挙を証明できなければエラーで終了し、
  一部の解だけで一致・一意と判定しません。未指定時は独立列挙の結果だけで、`models_verified=false` を記録します。
- 有効な全盤面サイズ、矛盾する矢印配置、全4矢印方向、既存ヤジリンとの一致、
  補助変数と射影の違い、CLI の異なる hash seed での再現性をテストします。すべての矢印配置をテストしたわけではありません。

`minimal_conflict` は**この土台・配置**で規則の任意の1つを外すと成立する、不成立の規則集合です。
制約追加が単調なため部分集合として極小ですが、一般の矛盾核や最少ヒントを求める機能ではありません。
`redundant_on_this_layout` は外しても解集合が同じという意味で、両方0解の場合も含みます。
2×2で冗長な単一サイクル規則も2×4では重要です。観測した配置以外へ一般化できません。

生成・ヒント削減・保存・表示は既存の [ヤジリン合成例](yajilin-composition.md)を使います。
この比較レポートから異なる規則構成を直接生成する機能、任意DSL規則の読み込み、
人間の解きやすさ評価、探索結果の順位付けは未対応です。

全候補と残ったヒントで規則の寄与が変わることは、[異種合成の固定ヒント比較](coupled-clue-contribution.md)で再現できます。
