# 数字の周囲の黒マス数を固定する

`AdjacentBlackCounts(neighbor_counts, diagonal=True)` は、数字マスを白にし、周囲8マスの黒数をその数字と等しくします。
自身は数えません。端や角では盤面内にある隣接マスだけが対象です。数字のないマスは白にも黒にもなれます。
これは [GMPuzzles のマインスイーパーの規則](https://www.gmpuzzles.com/blog/minesweeper-rules-and-info/)の隣接黒数です。
黒の総数・連結・非接触は要求しません。必要なら既存の別ルールを足します。

`diagonal=False` は上下左右4マスだけを数える変種です。通常の8近傍マインスイーパーとは区別してください。
例えば3×3の中央に4がある場合、8近傍なら周囲8マスから黒4個を選び、4近傍なら上下左右全てを黒にし、角4マスは制限しません。

## 数字なしと0を区別する

| データ | 意味 |
| --- | --- |
| `null` / Pythonの `None` / 入力欄の `.` | 数字なし。この断片からは何も要求しない |
| `0` | 実際の数字ヒント。数字マスと、その対象の隣接マスを全て白にする |
| `1`〜`8` | 数字マスを白にし、隣接黒数を一致させる |

全て `null` なら、この断片は何も絞りません。全て0なら全白になります。
これは[可視数](white-visibility.md)や[島の面積](white-island-areas.md)の「0は数字なし」と異なるため、新しい `clue-grid` 入力を使います。
既存の `number-grid` の意味を変更せず、そちらでは `null` を引き続き拒否します。

## 小さな例を生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-minesweeper-recipe.json --selection finite --seed 0 --output mines.json --quiet
uv run --no-sync python examples/generate_shading.py show mines.json
uv run --no-sync python examples/generate_shading.py verify mines.json
uv run --no-sync python examples/generate_shading.py check mines.json --answer ".../..#"
```

[2×3の例](../examples/shading-minesweeper-recipe.json)の固定数字は次のとおりです。この断片だけで一意になり、追加のセルヒントも黒総数も不要です。

```text
0 . 1
. 1 .
```

数字の配置と値は基礎ルールに固定されます。生成器は数字を選定・削減せず、別の設定で曖昧さがあれば、選ばれたセル等のヒントを残します。
この例に黒総数2を足すと矛盾します。数字付きマスは黒総数にも隣接黒数にも黒として数えられません。
`show` は0を消さずに表示し、数字マスは既知の白とします。完全解は表示しませんが、保存JSON自体には答えが入っています。
PCゲームの自動展開・クリックによる地雷判定・プレイ履歴は実装していません。完成した黒白配置を検証する、ペンシルパズルとしての例です。

```python
from puzzle_defs import AdjacentBlackCounts, ShadingRecipe

recipe = ShadingRecipe(2, 3, (
    AdjacentBlackCounts(((0, None, 1), (None, 1, None))),
))
```

## UIと入力契約

宣言は `neighbor_counts/clue-grid` と `neighbor-counts/cell-neighbor-counts`、斜めを含むかの真偽値です。
Webでは「数字の周囲の黒マス数を固定」を選び、数字なしを `.`、数字0を `0` と入力します。JSONでは `null` を使い、文字列 `"."` は受理しません。
上の例だけを試すときは、既定の「黒マスの個数」と「白マスをつなぐ」を外し、この断片だけを選んでください。
入力欄で文字列 `null` を書くこともできません。セル表示は「隣0」等で区別し、0を含む全ての数字マスは白として固定します。
サーバー側でも0を条件として検査し、ブラウザは0から `null` への改変を別の問題として拒否します。

通常ラベル・可視数・島の面積・隣接黒数は別の格子として保持できます。部屋境界も重ねられます。
併用時は数字の意味を盤面の説明と読み上げに示し、隣接黒数と他の数字を重ねる盤面のセルを広げます。
同じ構文・位置・値でも異なる意味を暗黙に共有しません。UIが適合しても、ルールや個数の組合せが成立するとは限りません。

保存IDは `adjacent-black-counts`、フィールドは `neighbor_counts` と `diagonal` です。既知の型に復元し、データからコードを実行しません。
数字なしを含む非空の長方形配列と厳密な0〜8の整数、真偽値を検査します。真偽値を数字扱いせず、小数・負数・9以上・凹凸・空・未知フィールドを拒否します。
数字が盤面内の対象隣接数を超えると、有効な入力だが矛盾するモデルです。4近傍で5〜8を指定した場合も同様です。
ファイル/UIで同じ表示を使う複数の隣接黒数ルールは、同じ格子を共有します。

## 範囲と検証

制約は既存の隣接ペア・8近傍ペアと線形和で構成し、回答は黒白セルだけに射影します。
保存CLIは既存の25セル上限、Web・有限判定は9セル上限です。Webは既存の計算予算を維持し、通常CLIに壁時計の上限はありません。
この断片の説明推論は未対応です。唯一解検証では適用し、推論では未対応番号を残します。ヒントの既約性は固定数字の最小化や人間の難易度を保証しません。

小盤面の全配置を、方向オフセットで作るビットマスク、別の距離計算による有限判定、DSLの回答集合で比較します。
0と数字なし、端、4近傍と8近傍、既存の数格子の拒否契約、保存・表示・解答確認も扱います。任意のサイズ・ルール全般の性能や、人が必ず論理だけで解けることは保証しません。
