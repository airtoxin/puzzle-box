# 小盤面でルールの組合せを探す

`examples/explore_shading.py` は、候補ルールの**すべての部分集合**を比較する探索例です。
[小盤面診断](shading-diagnostics.md)の有限検査器とヒント抽出の定義を再利用し、
成立性、完成解の集合、ルールを1つ外した影響を調べます。通常の生成器は変更しません。

## まず16通りを比較する

リポジトリのルートで実行します。

```sh
uv sync --all-packages --group dev --locked
uv run --no-sync python examples/explore_shading.py
uv run --no-sync python examples/explore_shading.py --explain 1 4
```

既定は2×2で、候補は次の4つです。番号は表示順の1始まりです。

1. 黒マス2個
2. 黒マスの縦横非隣接
3. 白マスの非空・縦横連結
4. 白だけの2×2を禁止

全16部分集合のうち14が成立し、12の部分集合には全行列ヒントで一意にできる完成解があります。
異なる完成解集合は11種類です。ルールなしの空集合も基準として含めます。
すべての候補を必ず採用するという意味ではありません。

| 選ぶ候補 | 完成解 | 全候補ヒントで一意になる完成解 | 判断できること |
|---|---:|---:|---|
| 1: 黒2個 | 6 | 4 | 行列ヒントでは2つの対角配置を区別できない |
| 1+4 | 6 | 4 | この2×2では黒2個なら白だけの2×2にならず、4は完成解集合を変えない |
| 1+2 | 2 | 0 | 行列ヒントは全行・全列が1になり、どの完成解も区別できない |
| 1+2+3 | 0 | 0 | ルールが矛盾しているため、冗長性は判定対象外 |

`Answer-set class` が同じ行は、**この寸法での完全な黒白配置の集合が同じ**です。
番号は各レポート内でのみ有効です。
回転・反転の同一視や、別サイズでのルールの同値性を表してはいません。
例えば「黒2個なら白2×2禁止は不要」という関係は、3×3には一般化できません。

## ルールが唯一解に寄与する例

```sh
uv run --no-sync python examples/explore_shading.py --rows 3 --cols 3 --black-counts 3 --candidates count non-touching --explain 1 2
```

この組合せには22解あり、全行・全列の黒数で16解を一意にできます。

- 黒数ルールを外すと41解増えますが、もともと一意だった16解は全行列ヒントがあれば一意なままです。
  全行列の黒数から合計の黒数も分かるためです。
- 非隣接ルールを外すと62解増え、もともと一意だった16解のうち12解が一意でなくなります。

後者の反例は次のように表示されます。行の黒数は `0, 1, 2`、列の黒数は `1, 1, 1` で共通です。

```text
元の答え    非隣接を外すと追加される答え
...         ...
.#.         ..#
#.#         ##.
```

非隣接ルールがあると左の答えだけですが、外すと右の答えも同じヒントを満たします。
JSONには元の答え・追加される答え・共通の全候補ヒント・元々一意だったかを保存します。

## 3つの比較を区別する

| 項目 | 比較しているもの |
|---|---|
| `redundant_without_hints` | ヒントなしでルールを1つ外しても完成解集合が同じか |
| `redundant_given_full_hints` | 元の各完成解から抽出する全候補ヒントを固定したとき、そのルールを外して候補が増える完成解が1つもないか |
| `uniqueness_lost_completions` | 全候補ヒントで元々一意だった完成解のうち、そのルールを外すと複数解になるものの数 |

比較の基準は、**選んだ部分集合・寸法・ヒント形式**です。全候補ヒントを固定しているので、
セルヒントを全マス残す場合は、どのルールを外しても答えは固定されています。
これは「生成してヒントを削減した後もそのルールが不要」という意味ではありません。
例えば2×2・黒1個で3マスが白と分かっている問題では、黒数ルールを外すと残る1マスを決められなくなります。

不成立の部分集合は冗長と分類せず `null` / `n/a` にします。
元々一意になる完成解が0個の場合も、一意性への寄与は `n/a / 0` とし、「寄与なし」と結論しません。
一方、同じヒントで候補が増えるかどうかは複数解の場合にも比較できます。

**個別に冗長なルールを、一度に全部消してよいわけではありません。**
同じ黒数ルールが2つあれば片方ずつは冗長ですが、両方を消すと黒数制約がなくなります。
この探索はルールの自動削除を行わず、削除を判断するときの根拠を表示します。

## 候補を増やす・実際の生成へ進む

```sh
uv run --no-sync python examples/explore_shading.py --black-counts 1 2 --include-diagonal --json --output combinations.json
```

`--black-counts` は黒数の候補を複数追加します。`--include-diagonal` は縦横非隣接に加えて
斜めも禁止する候補を追加します。この例は6候補・64部分集合です。
黒1個と黒2個の同時採用など、不成立の部分集合も比較対象になります。
`--allow-empty-white` は白連結候補で白0個を許します。
`--candidates` や `--hints` の後を空にすると、候補なし・ヒントなしも調べられます。

`--explain 1 2` は1つの部分集合の削除効果を詳しく表示します。
`--json` は全結果、`--output` は全結果のJSON保存です。JSONには反例の答えも含みます。
`--json` と `--explain` は併用できません。診断上の矛盾は結果なので終了コード0、不正入力は2です。

選んだ組合せを、既存の生成例に渡せます。例えば3×3の黒3個・非隣接にセルヒントも許す場合です。

```sh
uv run --no-sync python examples/explore_shading.py --rows 3 --cols 3 --black-counts 3 --candidates count non-touching --hints cell row-count column-count --explain 1 2
uv run --no-sync python examples/generate_shading.py generate --rows 3 --cols 3 --rules count non-touching --black-count 3 --hints cell row-count column-count --seed 6 --output found.json
uv run --no-sync python examples/generate_shading.py verify found.json
```

Python 3.12.14 / OR-Tools 9.15.6755の上記例では、削減後に `row=0, count=1` と
`row=1, count=2` の2ヒントだけが残りました。唯一解と各ヒントの必要性を検証済みです。
これはヒント削減後の実例であり、全候補ヒントを固定した冗長性の判定とは区別します。

行列ヒントだけのように一意にできる完成解とできない完成解が混ざる場合、
生成器が最初に選ぶ完成解で成功するとは限りません。探索結果はseedの成功率や難易度の順位ではありません。

## 探索範囲と一般化できないこと

- 最大9マス（512配置）、8候補出現（256部分集合）。すべての組合せ・全配置を調べます。
  各ルールの適合配置とヒントの署名を共有し、組合せごとに全ルールを再解釈したり求解したりはしません。
- 対応は[保存形式に対応する組み込みルール](composable-shading.md)の厳密な型、セル・行黒数・列黒数の3ヒント形式です。部屋配置の自動列挙はしません。
  カスタムルールやサブクラス、領域・ループ・ヤジリンは未対応です。
- 有限検査器はルールの意味を別実装しているため、ルール変更時には更新が必要です。
  テストでは全部分集合と各削除の結果を実際のDSLの全回答・ヒント抽出と照合します。
- 同値・冗長・一意性への寄与は、この小盤面と全候補ヒントに関する性質です。
  別サイズ、削減済みのヒント、人間向け難易度、面白さ、均一な生成分布へ一般化しません。
- 最大件数は実行時間やメモリの厳密な上限ではありません。一般の大盤面探索へ拡張していません。
