# 角で接する成分の面積を異ならせる

`UnequalCornerComponentSizes(black=True)` は、対象色の別々の上下左右連結成分が角で接するとき、面積を異ならせます。
対象色は黒が既定で、`False` にすると白です。同じ成分内の角接触は比較せず、離れた同面積の成分は許します。
長さや形の一致、すべての成分の連結、対象色の存在は要求しません。成分のない場合も条件を満たします。

[Jankoによるぬりぼうのルール](https://www.janko.at/Raetsel/Nuribou/index.htm)では、黒の成分を幅1マスの直線にし、同じ長さの棒の角接触を禁止します。
この断片は面積比較だけを取り出します。直線なら面積と長さが同じですが、直線以外にも適用できます。
同じ形かどうかを比べる[LITSの接触条件](tetromino-contact.md)や、すべての成分に角接触相手を要求する[成分の角接触](corner-linked-components.md)とは独立です。

## 4断片でぬりぼうの小さな例を作る

[3×3の保存レシピ](../examples/shading-nuribou-recipe.json)は次の固定入力を使います。

```python
from puzzle_defs import (NoBlack2x2, RectangularComponents, ShadingRecipe,
                         UnequalCornerComponentSizes, WhiteIslandAreas)

recipe = ShadingRecipe(3, 3, (
    WhiteIslandAreas(((0, 0, 1), (0, 5, 0), (0, 0, 0))),
    RectangularComponents(black=True),
    NoBlack2x2(),
    UnequalCornerComponentSizes(black=True),
))
```

白い島ごとに数字をちょうど1個置き、数字は面積と一致させます。数字セルは白です。
黒の長方形条件と黒2×2禁止を組み合わせると、黒の各成分は幅1マスの直線になります。
最後に新しい断片で、角で接する黒い棒を異なる長さにします。
ルール名だけを選んで白の全連結を追加すると、複数の白い島を許すこの設定とは異なる問題になるので注意してください。

最初の3条件には3個の完成盤面があります。新条件を加えると `.#./..#/..#` と `##./..#/...` の2個になります。
除かれる `.#./..#/#..` では、同じ面積1の別々の黒成分が角で接しています。
有効な2個では、面積2の棒と面積1の棒が角で接しています。
ルールだけでは一意でないため、生成器は必要な追加セルヒントを残します。白の成分を比較する設定へ変えると、この固定例では3個の完成盤面が残ります。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-nuribou-recipe.json --selection finite --seed 0 --output nuribou.json --quiet
uv run --no-sync python examples/generate_shading.py show nuribou.json
uv run --no-sync python examples/generate_shading.py verify nuribou.json
```

`show` は数字・残ったヒント・ルールと入力用の盤面を表示します。`--reveal` を付けると答えを表示します。
保存JSON自体には完全解が含まれます。固定数字の自動配置や最小化を行う生成器ではなく、追加セルヒントを削減する限定的な例です。
追加ヒントの既約性は、固定数字の最少性や人間の難易度を保証しません。

## Webで使う

[Webアプリ](web-app.md)の黒白セルを3行3列にし、初期の黒個数・白連結を外します。
「白い島の面積を数字に合わせる」「連結成分を長方形にする」「黒い2×2を禁止」「同じ大きさの成分の角接触を禁止」を選びます。
島の面積の入力は `0 0 1 / 0 5 0 / 0 0 0` を行ごとに入力し、0は数字なしとして扱います。
長方形と面積比較の対象色は両方とも黒にします。ヒントはセルを選び、行・列の黒数を外すと保存例と同じです。

新ルールが宣言するのは真偽値の色選択と `answer/binary-cells` です。
既存の黒白入力と白い島の数字表示を再利用し、生成・正誤確認・保存に使います。内部の候補列挙用領域は、入力する部屋や画面の部屋境界ではありません。
数値の表示ができることと、選んだルールの成立性は別です。例えば、全成分を同じ面積にしつつ角接触相手を必須にすると、対象色を含む盤面を作れません。

## 入力契約と検証範囲

保存IDは `unequal-corner-component-sizes`、パラメータは `black` だけで、厳密な真偽値が必要です。
0・1・文字列・小数・null、未知・欠落フィールド、独自サブクラスの暗黙の保存を拒否します。
旧読込器は新IDを拒否し、ファイルからimportや任意コードを実行しません。既存IDの意味は変更しません。
Python・保存形式では同じルールを繰り返せますが、Web要求のID重複は既存仕様どおり拒否します。

Python・保存形式・Webとも、この断片の盤面は9セル以下です。Webと有限診断は引き続き最大8ルールです。
サイズ上限は成分候補の組合せを制限するためで、任意の大きさのぬりぼうに対応するものではありません。
上限超過は候補列挙前に拒否します。ループなど別のWebプロファイルへの変換は行いません。
専用の説明推論は未対応と報告し、求解・一意性検証には新しい制約を適用します。

実装は既存の成分候補と最大性の制約を、盤面全体の1領域として再利用し、角で接する同面積の候補の同時選択を禁止します。
内部の候補変数は補助変数で、答えの射影は黒白セルだけです。利用者が入力する部屋で区切った局所成分の面積は比較しません。
小盤面では、独立の洪水探索とunion-findによる成分分割を照合します。
6セル以下ではCSPの全完成集合とも比較し、3×3は全512配置の独立検査同士、境界例と固定例のCSPを照合します。
全9セル配置のCSP列挙や、任意の組合せ・サイズ・環境での性能を網羅した保証ではありません。
