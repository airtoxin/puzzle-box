# 数字セルが属する成分の面積を指定する

`ComponentAreaClues(component_areas)` は、数字セル自身が属する**同色の上下左右の成分**のマス数を指定します。
数字セル自身も数えます。セルの色は固定せず、黒にも白にもできます。
[ニコリ公式のチョコバナナ](https://www.nikoli.co.jp/ja/puzzles/choco_banana/)にある数字の条件を、形や色の条件と独立した断片にしています。
Python・ファイル・Webとも、盤面全体で9セル以下に限定します。

## 既存の数字との違い

| 条件 | 数字が表すもの | 数字セルの色 |
| --- | --- | --- |
| この断片 | 自身を含む同色の成分の面積 | 黒・白のどちらも可 |
| `WhiteIslandAreas` | 白成分の面積。各白成分に数字を1個要求 | 白に固定 |
| `WhiteAreaClues` | 数字がある白成分の面積 | 白に固定 |
| `AdjacentBlackComponentSum` | 隣接する異なる黒成分の面積合計 | 白に固定 |

この断片は、同じ成分に同じ数字が複数あっても、数字がない成分があっても許します。
同じ成分の数字どうしが異なれば矛盾します。数字なしのセルは、色にも成分サイズにも追加の条件を課しません。
0は「数字なし」です。隣接黒数や Tapa の0ヒントとは異なり、面積0の成分や白い数字セルを意味しません。

例えば1行の部屋なし盤面で、面積2を左端だけに指定すると、`白・白・黒` と `黒・黒・白` の両方が通ります。
数字セルを白と決めつけたり、黒白どちらの成分にも別々の数字が必要としたりしません。

## チョコバナナ型の例を生成する

[2×3のレシピ](../examples/shading-choco-banana-recipe.json)は、次の固定数字に、黒の成分を長方形にする条件・白の成分の長方形を禁止する条件を加えます。

```text
1 0 0
0 0 4
```

この3条件で一意に決まり、追加のセルヒントは不要です。数字1のセルは黒、数字4のセルは白になります。
これは数字の入力時に色を固定した結果ではなく、成分の面積と形の条件から決まる色です。
黒全体や白全体の連結、黒の非接触、黒2×2禁止は暗黙に加えません。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-choco-banana-recipe.json --selection finite --seed 0 --output choco-banana.json --quiet
uv run --no-sync python examples/generate_shading.py show choco-banana.json
uv run --no-sync python examples/generate_shading.py verify choco-banana.json
uv run --no-sync python examples/generate_shading.py check choco-banana.json --answer "#.#/..."
```

`show` は数字とルールを表示し、両方の数字セルも `?` のままにします。完全解を表示しませんが、保存JSONには答えが含まれます。
数字の配置と値は固定で、生成器が選定・削減しません。曖昧な別の設定では、選んだ種類のヒントを必要に応じて残します。
唯一解・ヒントの既約性は、固定数字の最小化や人間の難易度を保証しません。

```python
from puzzle_defs import (
    ComponentAreaClues, NonRectangularComponents, RectangularComponents, ShadingRecipe,
)

recipe = ShadingRecipe(2, 3, (
    ComponentAreaClues(((1, 0, 0), (0, 0, 4))),
    RectangularComponents(black=True),
    NonRectangularComponents(black=False),
))
```

## UIと保存契約

Webで「数字セルが属する成分の面積を固定」を選び、空白区切りの整数を行ごとに入力します。
上の例では初期の黒総数・白連結を外し、「連結成分を長方形にする」（黒）と「連結成分の長方形を禁止」（白）を加えてください。
「面1」等のラベルで表示し、解答は数字セルも含めて黒白を入力します。別のルールや残ったヒントが色を固定する場合は、それに従います。

宣言は `component_areas/number-grid` と `component-areas/cell-component-areas` です。
白い島の `areas`、可視数、固定ラベル、隣接黒数、黒成分の面積合計、Tapa の区間、端点の丸とは別の格子として保持します。
意味を暗黙に共有せず、同じセルに重なる数字を別の位置と読み上げで区別します。表示欄が対応していても、数値やルールが数学的に両立するとは限りません。
ブラウザはチャンネルと格子が要求した値に一致することを検査し、欠落・改変・未要求の追加を無視せず拒否します。

保存IDは `component-area-clues`、フィールドは `component_areas` です。
非空の長方形配列と厳密な0〜99の整数を使い、不変の格子へコピーします。
`null`・真偽値・小数・負数・100以上・凹凸・盤面との寸法不一致・未知のフィールドを拒否します。
盤面より大きい正の面積は、この数値範囲内なら有効な入力ですが、満たせないモデルです。例えば1セルに99を指定すると矛盾します。
ファイル/UIでこの表示を共有する複数の出現は、同じ数字格子が必要です。
既知の型に明示的に復元し、データからコードを実行しません。古い読込器は新IDを拒否します。

## 実装と範囲

各数字について、数字セルを含む指定面積の連結領域を列挙します。
領域の内部を同じ色、その外周を反対色とする候補を、黒・白の両方について作り、既存の `one_of` で表します。
数字セルが属する最大の同色成分は1つだけなので、これらの候補は互いに排他的です。
補助変数の代入ではなく、既存の黒白セルへ射影して解の一意性を判定します。

独立判定は数字セルから同色をたどります。参照テストは別の union-find で各セルの所属面積を計算します。
2×3以下では両色を含む全回答をDSL・独立判定・参照結果で比較し、3×3では全512配置の密な数字格子と改変した数字を独立判定で照合します。
色の自由、0、複数数字、数字のない成分、境界、上限、保存・合成レシピの表示、サーバー解答確認も検証します。

候補列挙は指数的なため、数字が全て0でも、コンストラクタで9セル上限を検査します。
保存問題の表示だけでも、上限を超える配置は受理しません。通常の保存CLIの25セル上限は、この断片の制限を広げません。
Webの計算予算を維持し、通常CLIには壁時計の打切りがありません。説明推論は未対応と報告し、唯一解検証では適用します。
任意の盤面型・任意のルールとの合成、最少ヒント数、論理だけでの解きやすさ、大きな盤面の性能は保証しません。
