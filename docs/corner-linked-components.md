# 各成分を別の成分と角でつなぐ

`CornerLinkedComponents(black=True)` は、対象色の各**上下左右の連結成分**に、別成分との斜めの接触を要求します。
[ニコリ公式のチェンブロ](https://www.nikoli.co.jp/ja/puzzles/chained-block/)にある「チェーンを作らないブロックを許さない」条件の断片です。
色の存在・個数、数字・「？」の配置、同じチェーン内の同形禁止は含みません。
同じ形のブロックでも、この断片では接触できます。回転・反転の形判定も行いません。

## 3種類のつながりを区別する

| 条件 | 対象 |
| --- | --- |
| `ConnectedBlack` | 黒全体を上下左右で1成分にする |
| `CornerConnectedColor` | 対象色全体を辺または角で1つにつなぐ。上下左右で1成分だけの場合も通る |
| `CornerLinkedComponents` | 対象色の各上下左右成分に、別成分との角の接触を要求する。複数のチェーンを許す |

同じ上下左右成分の内部に斜めの接触があっても、別成分との接触として数えません。
例えば2×2のうち3マスが黒いL字は、内部に角の接触があっても黒1成分なので違反します。
2つの黒い孤立セルが斜めに接する配置は通ります。対象色が0個の場合も通ります。
`black=False` は白を対象にする変種です。その場合も `BlackCount` や行列ヒントは黒の個数です。

複数チェーンの例は次の2×5です。4つの孤立した黒ブロックが2本のチェーンを作り、黒全体の8近傍連結は満たしません。
この10セルの例はPythonとWebで使えます。有限診断の9セル上限の外です。

```text
# . . . #
. # . # .
```

非空な対象色を上下左右で1成分にする条件と、この断片を同時に要求すると矛盾します。
空を許す条件どうしなら、対象色を0個にできる場合があります。非空を暗黙に加えることはありません。

## 生成して解く小さな例

[2×3のレシピ](../examples/shading-corner-chain-recipe.json)は、黒3マス・黒2成分・角での接続を組み合わせます。
黒2成分の条件は、盤面全体を1部屋とした既存の `RoomComponentCount` で表します。
この「部屋」は成分を数える範囲で、角でつながる2ブロックそのものを部屋に分けるものではありません。

```python
from puzzle_defs import BlackCount, CornerLinkedComponents, RoomComponentCount, ShadingRecipe

rooms = ((0, 0, 0), (0, 0, 0))
recipe = ShadingRecipe(2, 3, (
    CornerLinkedComponents(),
    RoomComponentCount(rooms, count=2),
    BlackCount(3),
))
```

1マスと2マスのブロックが角で接する4解があり、セルヒント2個で区別します。
同じ小盤面で他のルール構成と同じ完成集合になる場合があっても、各断片が一般に同じ意味になるわけではありません。
この例のセルヒントは、チェンブロの各ブロックに数字か「？」を置くヒントとは異なるため、通常のチェンブロ全体を実装した例ではありません。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-corner-chain-recipe.json --selection finite --seed 0 --output corner-chain.json --quiet
uv run --no-sync python examples/generate_shading.py show corner-chain.json
uv run --no-sync python examples/generate_shading.py verify corner-chain.json
uv run --no-sync python examples/generate_shading.py check corner-chain.json --answer "##./..#"
```

固定環境の seed 0 では上中央の黒・左下の白が残り、上の解答が通ります。
`show` は完全解を出しませんが、保存JSONには答えが含まれます。唯一解やヒント既約性は、最少ヒント数・人間の難易度を保証しません。

Webでは「各成分を別の成分と角でつなぐ」を選び、対象色を真偽値で指定します。既存の黒白表示を再利用し、専用の描画器は不要です。
上の例では初期の白連結を外し、黒数を3にし、部屋内の成分数2と全0の部屋配置を追加します。セルヒントだけを選べます。
別途黒全体の非空な連結を追加すると、UIは適合していても生成時に矛盾します。

## 入力と上限

保存IDは `corner-linked-components`、フィールドは厳密な真偽値 `black` です。
整数・文字列・省略・未知のフィールドを拒否し、既知の型へ明示的に復元します。データからコードを実行しません。
古い読込器は新IDを拒否し、スリザーリンクやセル中心ループのルールへ暗黙に変換しません。

Python・保存CLI・Webでは盤面全体で100セルまでです。他のルールと組み合わせると、そのルール固有の小さい上限が優先されます。有限全列挙による診断は別途9セルまでです。9セルを超える通常CLIの生成には `--selection solver` を使います。上限は入力可能なサイズであり、任意の条件や盤面で予算内に生成できる保証ではありません。

## 制約と検証

対象色の上下左右の成分に、成分内で共通のラベルを付けます。各対象セルは、ラベルが自身の番号である根か、深さが小さい上下左右の対象セルを親に持ちます。隣接する対象セルには同じラベルを課し、ラベルの上限をセル番号とすることで、根は成分内の最小番号になります。これにより、別の成分が同じラベルを持つことを防ぎます。

別ラベルの対象セルとの斜め接触を証拠として選び、各対象セルはその証拠を持つか、上下左右の対象セルを親とする別の深さ減少木で証拠へ到達します。したがって各成分に別成分との斜め接触が必要です。同じ成分内の斜め接触は証拠にならず、対象色が空の場合は条件を満たします。補助変数は見える回答に数えません。

独立判定は各上下左右成分をたどって外部の角接触を調べます。別の参照テストは union-find で4近傍成分と8近傍成分を作り、各8近傍成分が少なくとも2つの4近傍成分を含むことを確認します。3×3までの全配置を両色についてソルバーと独立判定で照合し、100セルの空集合・内部接触・複数チェーンも検証します。保存形式、生成した問題の唯一性、正誤確認も検証します。

6×6で黒6マス・白連結・黒の辺接触禁止・黒成分の角接触を組み合わせた例では、手元の10秒予算で約4.8秒で唯一解の問題を生成し、正解と1マス変更した回答の判定を確認しました。10×10のモデル構築は約0.46秒、Python側の `tracemalloc` ピークは約0.43 MiBでした。後者はCP-SATネイティブ側のメモリを含まず、求解時間の保証でもありません。Webの計算予算は維持し、時間切れは未確定として扱います。説明推論は未対応と報告し、唯一解検証では適用します。
