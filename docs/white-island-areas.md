# 白い島の面積を数字に合わせる

`WhiteIslandAreas(areas)` は、各白連結成分（島）に正の数字をちょうど1つ含め、その島の面積を数字と等しくします。
数字マスは白です。島は上下左右の接触でつながり、異なる島の辺接触はできませんが、斜めの接触は許します。
`0` は数字のない場所で、面積0の島ではありません。数字を含まない白い島も禁止するため、全て0なら全黒になります。
数字なしの白成分を許す場合は別ルールの [WhiteAreaClues](white-area-clues.md) を使います。このルールの意味は変わりません。

[ニコリのぬりかべ公式ルール](https://www.nikoli.co.jp/ja/puzzles/nurikabe/)の、島と数字の関係を切り出した断片です。
黒の連結は `ConnectedBlack(...)`、黒2×2禁止は `NoBlack2x2()` として別に組み合わせます。この断片だけでは黒の連結や2×2を制限しません。
長方形の島は要求せず、[固定サイズの成分](component-size.md)とも異なり、島ごとに別の面積を指定できます。

## 小さなぬりかべを生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-nurikabe-recipe.json --selection finite --seed 0 --output nurikabe.json --quiet
uv run --no-sync python examples/generate_shading.py show nurikabe.json
uv run --no-sync python examples/generate_shading.py verify nurikabe.json
uv run --no-sync python examples/generate_shading.py check nurikabe.json --answer ".#./##."
```

[2×3の例](../examples/shading-nurikabe-recipe.json)は、次の島の面積、黒連結、黒2×2禁止で一意になります。追加のセルヒントは不要です。
表示の `.` は数字なしで、データでは0です。

```text
1 . .
. . 2
```

数字と位置は生成中に固定され、削減するヒント候補とは別です。この機能は数字配置の自動選定・削減をしません。
他の数字配置では解なし・複数解になり、生成器が必要なセル等のヒントを残す場合があります。
`show` は数字マスを既知の白として表示し、完全解は隠します。保存JSON自体には答えも入っています。

```python
from puzzle_defs import ConnectedBlack, NoBlack2x2, ShadingRecipe, WhiteIslandAreas

recipe = ShadingRecipe(2, 3, (
    WhiteIslandAreas(((1, 0, 0), (0, 0, 2))),
    ConnectedBlack(False), NoBlack2x2(),
))
```

この例の `ConnectedBlack(False)` は黒0個を許す設定で、従来の `NurikabePuzzle` の空集合の扱いに合わせています。
黒を必ず置く場合は `ConnectedBlack()` を選びます。上の例の完成解にはどちらの設定でも黒があります。
従来の `NurikabePuzzle` の入力では数字なしを `None` としますが、この `areas` 格子では0です。`areas` に `None` は受理しません。
既存の専用ソルバーは変更せず、出力も従来どおり島の所有者番号です。合成レシピは黒1・白0を回答とし、比較テストで所有者番号を色へ変換します。

## Web の数字と UI 要求

「白い島の面積を数字に合わせる」を選ぶと `areas/number-grid` の入力と `island-areas/cell-island-areas` の表示を要求します。
面積の正の数字は四角で囲んで表示し、白として固定します。0は描画しません。
既定の黒総数・白全体の連結は、島の分離と衝突する場合があります。上の例ではそれらを外し、黒連結と黒2×2禁止を選んでください。

`numbers`（通常ラベル）・`counts`（丸で囲む白の可視数）・`areas`（四角で囲む島の面積）は別の入力です。
同じ `number-grid` 構文でもパラメータ名が違えば共有せず、それぞれの値と意味を保ちます。
併用時は通常ラベルを中央、可視数を左上、面積を右上に置き、読み上げにも意味を付けます。通常ラベルがなければ面積は中央に置きます。
丸数字だけのときも中央です。部屋境界とも重ねられます。既存の通常ラベル0は数値として表示し続けます。

UIを重ねられても、ルールが両立するとは限りません。上の例に部屋内の黒連結を足すと、既定のL型2部屋では、片方の部屋の黒2マスが斜めだけで接するため矛盾します。
部屋を上段と下段（`0 0 0 / 1 1 1`）に変えると成立します。黒が盤面全体で連結していても、部屋の内側だけでつながるとは限りません。

ブラウザは要求した面積格子・チャンネル・寸法・値との一致を検査し、欠落・改変・未要求の面積を黙って表示しません。
未知のルール・描画型は閉じたカタログの範囲外として拒否します。解答確認は全ての黒白値をサーバーで検査します。

## 入力と実装の範囲

- **この断片はPython・ファイル・Webとも9セル以下です。** 領域候補の列挙は指数的なので、格子の入力時に上限を検査し、超過は列挙前に拒否します。一般のCLIの25セル上限まで広がるわけではありません。
- 面積格子は0〜99の厳密な整数の長方形配列です。真偽値・小数・空・凹凸・範囲外・未知フィールドは拒否します。盤面より大きな正の数字は、有効な入力だが矛盾する制約です。
- 保存IDは `white-island-areas`、パラメータは `areas` だけです。同じ表示を使う複数の島ルールは同じ格子を共有します。新IDを知らない旧版は拒否します。データからコードは読み込みません。
- 島の説明推論は未実装です。唯一解の検証には使い、推論では未対応番号を残します。唯一解・ヒントの既約性は、最少の数字・人間の難易度・論理だけで解けることを保証しません。
- Webは既存のワーカー予算を使います。通常のCLI生成には壁時計の時間上限がなく、9セルの制限も厳密な実行時間の保証ではありません。

既存の連結領域列挙と `filter_number_equals_area` を再利用し、数字を1つ含み面積が一致する候補だけを残します。
各白マスを候補でちょうど1回覆い、選択した候補の外側の隣接マスを黒にして、候補が島全体になるようにします。
数字マスを白にする条件も明示し、数字を黒にして候補の選択を回避できないようにします。補助変数や島の所有者は回答の射影に含めません。
独立した白成分の検査、数字を起点とする別の探索、従来の専用ソルバーとの小盤面比較を行います。任意サイズ・全てのルールの組合せを証明するものではありません。
