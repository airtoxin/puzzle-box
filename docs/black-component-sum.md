# 隣接する黒い塊の面積を合計する

`AdjacentBlackComponentSum(component_counts)` は、数字マスを白にし、その上下左右に接する黒連結成分の面積を合計します。
同じ成分が複数の辺から接しても、その面積を1回だけ数えます。接続は上下左右で、斜めだけの接触では成分はつながりません。
[ニコリのクロット公式ルール](https://www.nikoli.co.jp/ja/puzzles/kurotto/)の、数字入りの丸と黒い塊の関係を切り出した断片です。
数字のない白丸には対応していません。直線上の[白の可視数](white-visibility.md)や、すぐ隣の[黒マス数](adjacent-black-counts.md)とは別の制約です。

たとえば3×3の中央に8を置き、周囲8マスをすべて黒にすると成立します。
周囲は1つの黒成分なので8です。4辺の接触ごとに8を加算した32でも、隣の4マスだけを数えた4でもありません。
複数の異なる成分が接すれば、その面積を足します。ある数字に接しない黒成分は、その数字の合計には含めません。

## 丸なしと0を区別する

| データ | 意味 |
| --- | --- |
| Python の `None` / JSON の `null` / Web 入力欄の `.` | 丸なし。そのマスの色をこの指定だけでは制限しない |
| `0` | 数字入りの白丸。上下左右に黒マスがない |
| `1`〜`99` | 数字入りの白丸。接する黒成分の面積合計を指定する |

数字のない白丸を `null` で代用すると白という条件が失われ、0で代用すると隣接黒を禁止します。
この形式はそのどちらも数字なし白丸として扱いません。全マス `null` なら、この断片は何も制限しません。
数字が盤面上で実現できる面積を超えていても、0〜99の範囲なら有効な入力です。そのモデルは解なしになります。

## 小さな例を生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-kurotto-recipe.json --selection finite --seed 0 --output kurotto.json --quiet
uv run --no-sync python examples/generate_shading.py show kurotto.json
uv run --no-sync python examples/generate_shading.py verify kurotto.json
uv run --no-sync python examples/generate_shading.py check kurotto.json --answer ".##/###"
```

[2×3の例](../examples/shading-kurotto-recipe.json)は、左上に5、残りに丸なしを指定します。
この数字だけで他の5マスがすべて黒に決まり、追加セルヒントは不要です。
1つの黒成分が左上の数字に2辺から接しますが、合計は5です。

```text
5 . .
. . .
```

`show` は数字マスを既知の白として表示し、数字格子を別に示します。完全解は隠しますが、保存JSON自体には答えが入っています。
黒2×2を禁止するルールは含まれません。この例に `NoBlack2x2()` を足すと解なしになります。
黒全体・白全体の連結や、すべての黒成分が数字に接することも要求しません。必要な条件は別の断片として加えます。

```python
from puzzle_defs import AdjacentBlackComponentSum, ShadingRecipe

recipe = ShadingRecipe(2, 3, (
    AdjacentBlackComponentSum(((5, None, None), (None, None, None))),
))
```

数字の配置と値はレシピの固定条件です。生成器が丸の位置や数字を選択・削減する機能ではありません。
別の配置で解が複数ある場合は、生成器が一意性に必要なセルヒントを残します。固定数字だけで一意になる保証はありません。

## Web と保存形式

Webでは「接する黒成分の面積合計を固定」を選びます。上の例だけを試すときは、初期選択の「黒マスの個数」「白マスをつなぐ」を外します。
入力は `component_counts/clue-grid`、表示は `component-counts/cell-component-counts` を宣言します。
丸に「塊5」「塊0」のように表示し、凡例と読み上げに意味を示します。0を含め、数字マスは白として固定します。
この表示は原作の数字だけの丸と区別した、このアプリの表記です。

固定ラベル・白の可視数・白い島の面積・隣接黒数・部屋の配置とは別の入力とデータです。
それぞれを同時に選べますが、表示できることはルールの成立を保証しません。
複数の数字の意味が重なる場合は位置と印を分け、読み上げにもすべて含めます。
ブラウザは要求した数字とサーバーの表示計画を照合し、欠落・0から `null` への変更・要求していない格子を拒否します。

保存ルールの ID は `adjacent-black-component-sum`、フィールドは `component_counts` だけです。
盤面と同寸の、丸なしまたは厳密な整数0〜99の長方形配列を受け付けます。JSONでは配列の配列を必須とし、文字列の `"."`、真偽値、小数、不揃い、未知フィールドを拒否します。
Python側では入力を不変な格子にコピーします。ファイル/UIで複数出現させる場合は同じ格子を共有する必要があります。Webでの同一ルールの重複選択は従来どおり拒否します。
既知の正確な組み込み型から構築し、データからコードを実行しません。未知IDを拒否する旧版の読み手は、この新IDも拒否します。

## 計算範囲と検証

この断片はPython API・保存ファイル・Webともに9セル以下です。コンストラクターで上限を確認し、候補列挙前に拒否します。
各数字以外のマスから黒成分の候補を列挙し、各黒マスが1候補に属し、有効な候補の外側に黒マスが接しないよう制約します。
数字に接する候補ごとに面積を1回加算します。候補の補助変数は回答に含めず、一意性は見える黒白セルで判定します。
全マス丸なしなら列挙しません。小盤面でも他の断片との組合せで計算量は変わり、Webは既存の計算予算を使います。通常CLIに壁時計の上限はありません。

有限検査器は黒成分全体を別に求め、テストの参照実装は各数字の隣から黒をたどった集合の大きさを数えます。
小盤面の全黒白配置でそれらとDSLの回答集合を比較します。複数辺での接触、複数成分、同じ成分を別々の数字で使う場合、数字に接しない成分、0と丸なしを含みます。
この限定検証から任意サイズの性能や、任意の組合せの成立を保証しません。
説明可能な推論手順はこの断片に未対応です。解検証には使いますが、推論では未対応ルールとして報告します。一意性から人間の解きやすさは判断しません。
