# 同色の連続長に上限を付ける

`RunLengthLimit(max_length=3)` は、黒・白のどちらも、縦横に同じ色が続く長さを指定値以下にします。
斜めの並びや曲がる経路、連結成分全体の面積は数えません。長方形の部屋や部屋境界にも依存しません。

[Grandmaster Puzzles の Aqre ルール](https://www.gmpuzzles.com/blog/aqre-rules-and-info/)では、黒をひとつながりにし、数字のある部屋では黒数を指定し、
黒・白とも縦横の4連続以上を禁止します。最大長3はこの最後の条件です。
最大長2は既存の `NoThreeConsecutive()` と同じで、2つのクラスは窓に制約を加える処理を共有します。
既存クラス・保存ID `no-three-consecutive` の意味やパラメータなしの形式は変わりません。

## 部屋・黒連結と組み合わせる

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-aqre-fragment-recipe.json --selection finite --seed 0 --output runs.json --quiet
uv run --no-sync python examples/generate_shading.py show runs.json
uv run --no-sync python examples/generate_shading.py verify runs.json
```

[保存例](../examples/shading-aqre-fragment-recipe.json)は1×6の1部屋に、黒2個・黒連結・最大連続長3を組み合わせます。
黒2個と連結だけなら隣り合う黒2マスの位置は5通りあります。両端の配置では白が4連続になるため、最大長3を加えると3通りです。
必要なセルヒントを残して一意にします。追加の黒白ヒントを含む小さな合成例で、一般の Aqre の数字配置や部屋を自動生成する機能ではありません。
部屋ごとに異なる数字・数字なしの部屋を混ぜる一般の出題形式も未対応です。

最大長を2に変えると、中央の黒2マスに決まり、追加セルヒントは不要です。最大長1では黒2個の連結と矛盾します。
`NoThreeConsecutive()` に置き換えてもよいのは最大長2の場合です。最大長3の代わりに使うと、より強い別の条件になります。

[Webアプリ](web-app.md)の黒白セルでも同じ例を試せます。
既定の黒数・白連結を外し、1行6列にして、部屋の黒数2・黒連結・連続長上限3を選びます。部屋入力は `0 0 0 0 0 0` の1行です。
表示・解答確認・保存は既存の黒白と同じです。この部品は整数パラメータと `answer/binary-cells` だけを要求し、専用描画器は不要です。

## パラメータと限界

- Pythonと保存レシピの `max_length` は厳密な正の整数です。真偽値・0・負数・小数・文字列を拒否します。
- Webの入力範囲は1〜25です。Pythonや保存レシピでは、それより大きい正の整数も許します。
- 全ての行・列が上限以下の長さなら、この断片は冗長です。大きな値をソルバーの整数境界へ入れず、その場合は制約を加えません。
- 3×3以下で最大長3なら冗長です。4マス以上の縦横が必要な条件なので、細長い例で違いを確認してください。
- `NoThreeConsecutive()` や複数の連続長上限を併用すると、一番小さい上限が有効です。行列の白黒同数・重複禁止・連結などの代わりにはなりません。

保存IDは `run-length-limit`、パラメータは `max_length` だけです。既知ID・厳密な型だけを扱い、任意コードは読み込みません。
保存CLI・黒白Webは最大100セル、Webは最大8ルールです。有限選択・診断は9セルまでです。組み合わせるルールに固有の上限があれば、より小さい方が適用されます。Webは時間予算付きで、通常CLI生成には壁時計の上限はありません。
[説明推論](shading-deductions.md)にこの断片の手順はなく、最大長2の場合も、未対応のルール番号として報告します。

実装は長さ `max_length+1` の各窓に黒と白を両方要求します。有限検査は別の方法で、各行・列を同色の連続区間に分けて長さを数えます。
小盤面の全回答を照合していますが、任意サイズ・全ルール組合せや人間向け難易度の保証ではありません。

[斜めの連続長](diagonal-run-limit.md)は独立した断片です。斜めを追加しても、この縦横の上限や既存IDの意味は変わりません。
