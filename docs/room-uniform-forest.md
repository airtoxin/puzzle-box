# 部屋の単色と同色の輪なしを組み合わせる

[ぬりめいずの公式ルール](https://www.nikoli.co.jp/ja/puzzles/nurimeizu/)から、部屋を単色にする条件と、白の輪を禁止する条件を別の断片として使えます。
既存の白連結・黒2×2禁止・白2×2禁止とも組み合わせられます。
S/G、丸・三角、最短経路への所属は扱いません。これらを組み合わせるだけで完全なぬりめいずになるわけではありません。

| 断片 | 条件 | 含まれない条件 |
| --- | --- | --- |
| `UniformRooms(rooms)` | 固定された各部屋をすべて黒またはすべて白にする | 部屋間の色の違い、黒数、全体の連結 |
| `AcyclicColor(black=False)` | 白マスの上下左右の接触で輪を作らない | 白の存在・連結、枝分かれの禁止 |
| `AcyclicColor(black=True)` | 同じ輪なし条件を黒に適用する変種 | 黒の存在・連結、白の輪の禁止 |

単色の部屋は、同じ色の隣の部屋と接してもかまいません。1マスの部屋はどちらの色でも条件を満たします。
輪なしは対象色が0個でも、孤立点や複数の木になっていても成立します。必要なら `ConnectedWhite()` / `ConnectedBlack()` を足します。
枝分かれは禁止しないため、[端点と次数で作る1本道](cell-path-fragments.md)とは異なります。

## 接する辺をすべて調べる

輪なしは、対象色のマスを頂点とし、上下左右で接するすべての対を辺とするグラフに対する条件です。
辺の一部を無視して木を選ぶ条件ではありません。プレイヤーが線を選択するパズルでもなく、答えは従来の黒白セルです。
斜めだけの接触は辺になりません。

3×3で中央だけが黒なら、外周の白8マスは輪になり `AcyclicColor()` に反します。
この配置に白2×2はないため、`NoWhite2x2()` だけでは輪なしを表せません。
逆に、黒だけに輪なしを指定した場合、この白い輪は許されます。
対象色を非空かつ連結にすると1つの木になりますが、その木には枝分かれがあってもかまいません。

## 小さな部屋の例を生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-room-forest-recipe.json --selection finite --seed 0 --output room-forest.json --quiet
uv run --no-sync python examples/generate_shading.py show room-forest.json
uv run --no-sync python examples/generate_shading.py verify room-forest.json
```

[2×3の例](../examples/shading-room-forest-recipe.json)は次の2部屋です。部屋番号は色や数字ヒントではありません。

```text
0 0 1
0 1 1
```

部屋の単色・白の輪なし・非空の白連結・黒白それぞれの2×2禁止を使います。
ルールだけでは「左の部屋を黒」「右の部屋を黒」の2解があり、生成器はそれらを区別するセルヒントを1つ残します。
seedの違いでどちらを選ぶかは環境にも依存します。固定ルールだけで一意だとは扱いません。
`show` の解答テンプレートを埋め、`check room-forest.json --answer "行/行"` に黒 `#`・白 `.` を渡すと確認できます。
完全解は表示時に隠しますが、保存JSON自体には答えが入っています。

```python
from puzzle_defs import AcyclicColor, ConnectedWhite, ShadingRecipe, UniformRooms

# 左は2×2の部屋、右は縦2マスの部屋。
recipe = ShadingRecipe(2, 3, (
    UniformRooms(((0, 0, 1), (0, 0, 1))),
    AcyclicColor(), ConnectedWhite(),
))
```

この別の組合せは、左を白にすると輪になるため左が黒、白を1つ以上要求するため右が白となり、セルヒントなしで一意です。
ただし黒2×2が存在します。ここに `NoBlack2x2()` を足すと解なしです。完全なぬりめいずの例ではありません。
単色の3マス部屋と `RoomBlackCount(..., 1)` の併用も解なしです。UIの互換性は数学的な成立を保証しません。

## UI・保存・互換性

Webでは「部屋内を同じ色にする」「同色マスの輪を禁止」を選びます。輪なしの対象は初期値が白です。
黒を選ぶ真偽値は厳密な `bool` を要求し、0/1や文字列を代用できません。
宣言型UIの既存 `rooms/cell-regions` と `answer/binary-cells`、部屋配置の入力、真偽値の入力を再利用します。
新しい描画器や線入力は必要ありません。部屋を使う他のルールと同じ正規化済み分割を共有し、同じ入力欄に統合します。
黒白以外のプロファイルにこれらのIDを渡すことはできません。

保存IDは `uniform-rooms`（フィールド `rooms`）と `acyclic-color`（フィールド `black`）です。
部屋は盤面と同寸で、各部屋の上下左右連結を検証し、番号を最初に出現する順に正規化した不変のコピーを保持します。
JSONは配列の配列を必須とし、空・不揃い・真偽値のラベル・非連結な部屋・未知フィールドを拒否します。
正確な組み込み型だけを保存し、クラスの継承で変えた意味を親型に置き換えません。データから任意コードを読み込む形式ではありません。
既存IDの意味は変えず、新IDを知らない旧版の読み手は拒否します。

## 実装と検証の範囲

輪なしは、同色の隣接対が存在するとき、必ずどちらか1方向に向けます。各頂点の入次数を1以下にし、向きに沿って整数の順位が増えるようにします。
木なら任意の根から外に向けて条件を満たせます。一方、無向の輪に入次数1以下の向きを付けると有向の輪になり、順位の増加と矛盾します。
このため、隠れた向きで輪の1辺を無視することはできません。部屋の単色は部屋の代表セルとの等値で記述します。
`ShadingRecipe` は向きと順位を回答の射影から除外し、黒白セルだけで一意性を判定します。
直接 `Puzzle` に断片を適用する場合、補助変数を回答に含めないための `set_solution_vars` は呼出し側の責任です。

有限診断は、成分ごとに「辺数＝頂点数−1」を検査します。別のテスト参照実装は、次数0/1の頂点を順に取り除き、最後に輪が残るかで判定します。
DSLとの全回答比較は最大2×3です。参照実装同士は3×3の全512配置でも照合し、3×3の長い輪などは個別の求解テストに残します。
部屋の単色は各部屋に色を割り当てて独立に列挙します。
枝分かれ、孤立、空、複数成分、2×2を含まない輪、反対色の輪、補助変数の異なる割当、保存とWebでの組合せも対象です。
これらは有限の検証であり、任意サイズの性能を保証するものではありません。

保存CLIは既存の25セル上限、Web・有限診断は9セル上限です。Webは既存の計算予算を使います。通常CLIに壁時計の上限はありません。
生成器は部屋を選択・分割・削減せず、固定された部屋の下でセルヒントを削減します。
この2断片の説明可能な推論手順は未対応で、未対応のルール番号として報告します。一意性や木の形から人間の難易度は判断しません。
