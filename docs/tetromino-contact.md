# 部屋の同形テトロミノを接触させない

`NoTouchingEqualTetrominoes(rooms)` は、部屋ごとの黒配置がつながった4マス（テトロミノ）になる場合、
回転・反転して同じ形になる別の部屋のピースと辺で接触することを禁止します。斜めの接触は許します。
比較するのは**各部屋の黒配置全体**です。部屋内に5マス以上の黒がある場合などに、その中の4マスの部分集合をピース扱いしません。

[ニコリの LITS 公式ルール](https://www.nikoli.co.jp/ja/puzzles/lits/)の同形接触禁止を切り出したものです。
この断片自体は黒4個や部屋内の連結を強制しません。空・3マス・切り離された4マスなどは対象外で、別のルールで制限します。
初期の2×3の部屋配置では各部屋が3マスなので、この条件は冗長です。

## LITS の条件を組み合わせる

次の5断片で公式の条件を構成できます。

| 条件 | 断片 |
| --- | --- |
| 各部屋に黒4個 | `RoomBlackCount(rooms, 4)` |
| 各部屋の黒が部屋内で連結 | `RoomConnectedBlack(rooms)` |
| 黒全体が連結 | `ConnectedBlack()` |
| 全黒2×2を禁止 | `NoBlack2x2()` |
| 同形の部屋ピースの辺接触を禁止 | `NoTouchingEqualTetrominoes(rooms)` |

`ColorComponentSize(4)` は盤面全体の黒成分を4マスにするので、部屋内テトロミノの代わりにはなりません。
LITS の複数の部屋ピースは全体でつながり、黒成分の面積は4より大きくなります。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-lits-recipe.json --seed 0 --output lits-variant.json --quiet
uv run --no-sync python examples/generate_shading.py show lits-variant.json
uv run --no-sync python examples/generate_shading.py verify lits-variant.json
```

[4×4の保存例](../examples/shading-lits-recipe.json)は、上下2行ずつを別の部屋にします。
この部屋配置だけでは複数解なので、生成器が追加の黒白ヒントを残して一意にします。
**通常の部屋境界だけの LITS を自動生成する機能ではありません。** LITS の条件を使った、黒白ヒント付きの合成例です。
部屋の自動生成・変更・削減は行いません。`show` は解を隠しますが、保存JSONには完全な解を含みます。
この4×4は有限生成の9セル上限を超えるので、`--selection finite` は使いません。

## Web と入力の範囲

この断片のPython実装と保存CLIは25セル以下です。Webも25セル以下です。有限診断は9セル以下です。
したがって、上の4×4例はPython/CLIで試してください。ルールは既存の部屋入力と境界表示を共有し、異なる部屋分割の併用は拒否します。

Webの3×3で、部屋黒数4・部屋内連結・同形接触禁止を選び、部屋配置を次の3行にすると、O形とL形なので接触できます。

```text
0 0 1
0 0 1
1 1 1
```

ここに黒2×2禁止を足すと、左上のO形が禁止されて矛盾します。O形は接触ルール単独では除外しません。
2×4で上下を別部屋にして各部屋を黒4個にすると、同じI形同士が辺接触するため、この断片によって矛盾します。

保存IDは `no-touching-equal-tetrominoes`、パラメータは `rooms` だけです。既知ID・厳密な型・連結した部屋配置を検査し、任意コードは読み込みません。
黒数や連結を省くと、このルールが適用されない盤面も生成されます。「全ての部屋ピースがテトロミノ」とは保証しません。
この断片の推論手順は未実装です。9セル以下では未対応番号を報告し、それより大きい問題は説明推論の範囲外として拒否します。

## 実装と検証

既存の連結領域列挙とポリオミノの回転・反転を使い、各部屋内の4マス候補を分類します。
候補の補助変数は、部屋の黒配置全体がその候補と一致する場合に限って真になります。偽にして接触禁止を回避できないよう双方向に制約します。
形の接触ペア計算を再利用し、汎用の `non_touching` に渡します。盤面全体を敷き詰める能力を宣言しないので、既存の高水準制約の前提チェックも保ちます。
補助変数は回答の射影に含めません。比較は常に部屋の黒配置に対して行います。

小盤面では独立した座標変換による形の一致判定と照合し、4×4では部屋ごとに4セルの組合せを列挙して、連結・黒2×2・同形接触を別に検査します。
複数解のモデルが条件追加で絞られることを確認しますが、任意サイズ・全組合せや人間向け難易度の保証ではありません。
候補・接触ペアの数は部屋配置で変わり、25セル以下でも実行時間の保証はありません。通常のPython生成には壁時計の時間上限がありません。
