# 部屋を下から水平に満たす

`RoomFillLevels(rooms, black=True)` は、部屋内の対象色を下から水平に満たす条件です。
[Aquarium の公開ルール](https://www.puzzle-aquarium.com/)を参考に、固定された各部屋に空から満杯までの水位を選べる断片にしています。
既存の黒白セル・部屋表示・行列の黒数ヒントを再利用し、専用の描画器や新しい回答形式を必要としません。

## 水位と部屋の意味

同じ部屋の同じ行は、離れた区間も含めて全て同じ色になります。
ある行を対象色にすると、それより下にある**その部屋の全セル**も対象色です。
縦に直接隣り合うセルだけに条件を課すものではありません。
各部屋は別々の水位を選べ、空・満杯も許します。別の部屋の水位や盤外とは接続しません。

```text
部屋配置              この黒配置は不可
0 1 0                 . . .
0 1 0                 # . .
0 0 0                 # # #
```

部屋0の2行目は左右のセルが同じ高さなので、左だけを黒にできません。
部屋のくぼみや別の部屋を挟んでも、この水平条件を保ちます。
一方、部屋が上でつながる形では、水面より下の対象色が複数の成分に分かれる場合があります。
この断片は対象色の連結・非空・個数を要求しません。必要なら別のルールを加えます。
水の移動・流入・漏出・時間変化を計算する物理シミュレーションではありません。

`black=False` なら白を水に対応させる変種です。その場合も、`BlackCount` や行列ヒントは引き続き**黒の個数**です。
例えば縦3マスの部屋に黒1個を指定すると、黒を水とすれば上から `白・白・黒`、白を水とすれば `黒・白・白` になります。

## 生成して解く

[3×3の例](../examples/shading-aquarium-recipe.json)は、上の部屋配置とこの断片だけを基礎ルールにし、行列ヒントだけを候補にします。
基礎ルールには12通りの完成形があります。全候補の黒数で区別してからヒントを削減します。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-aquarium-recipe.json --selection finite --seed 0 --output aquarium.json --quiet
uv run --no-sync python examples/generate_shading.py show aquarium.json
uv run --no-sync python examples/generate_shading.py verify aquarium.json
uv run --no-sync python examples/generate_shading.py check aquarium.json --answer ".#./.#./..."
```

固定環境の seed 0 では、一番上の行の黒数1・一番左の列の黒数0が残ります。セルヒントは使わず、一意な完成形を検証します。
`show` は部屋と残った黒数を表示し、答えは出しません。保存JSON自体には答えが含まれます。
0とヒントなしは異なり、削減後に全ての行列に数字が残るわけではありません。
部屋は固定で、生成器が新しい部屋を分割したり、配置を削減したりする機能ではありません。

```python
from puzzle_defs import BlackCount, RoomFillLevels, ShadingRecipe

rooms = ((0, 1, 0), (0, 1, 0), (0, 0, 0))
recipe = ShadingRecipe(3, 3, (
    RoomFillLevels(rooms),
    BlackCount(4),
))
```

この組合せは、中央下の1マスと一番下の3マスを黒にする配置に決まります。
他にも黒の連結などを追加できますが、それは通常の Aquarium に対する追加条件です。
同じ配置に「各部屋の黒数を1個」を加えると矛盾します。部屋0の最小の非空な水位は一番下の3マスなので、黒1個にはできません。
UIで組み合わせられることと、数学的に成立することは別です。

## UI・保存・互換性

Webでは「部屋の対象色を下から水平に満たす」を選び、共有する部屋配置と、水に対応する色を入力します。
上の例を試すときは初期の黒総数・白連結とセルヒントを外し、行列ヒントを残します。
セルを一つずつ入力して完成形を確認します。クリックから水位を自動展開する専用操作はありません。

宣言は既存の `rooms/region-map` と `rooms/cell-regions`、および真偽値 `black` です。
黒白の回答と部屋境界を既存の描画器が合成します。他の部屋ルールと併用するときは、ラベルを振り直した後に同じ分割を共有する必要があります。
異なる部屋配置を同名チャンネルに重ねません。スリザーリンクやセル中心ループのルールとしては受理しません。

保存IDは `room-fill-levels`、フィールドは `rooms` と `black` です。JSONの `black` は省略せず、厳密な真偽値を使います。
部屋のラベルは0以上・面積未満の整数で、各部屋は上下左右で連結している必要があります。リストは不変のタプルへコピーし、ラベルを正規化します。
空・凹凸・寸法不一致・真偽値や小数のラベル・不連結な部屋・未知のフィールドを拒否します。
既知の型に明示的に復元し、ファイルからコードを実行しません。古い読込器は未知の新IDを拒否します。

## 実装と限界

DSLは部屋内の同じ行の変数を等しくし、隣り合う高さの代表変数に単調な不等式を加えます。
補助の水位変数は作らず、回答は既存の黒白セルです。
独立した有限判定は、各対象色セルから同じ高さ以下の部屋内セルを直接検査します。
参照テストは部屋ごとの水面の高さを全て選んで完成形を構成し、DSL・有限判定の回答集合と照合します。
対象は1行・1列・単独セル・L字・上下にくぼんだ3×3等の小盤面と両方の色です。

保存CLIは既存の25セル、Webと有限診断は9セルまでです。Webの計算予算を維持し、通常CLIには壁時計の打切りがありません。
説明推論はこの断片を未対応と報告します。唯一解検証には適用しますが、水位を使った説明手順を生成する機能ではありません。
唯一解・ヒントの既約性は、最少ヒント数・人間の難易度・任意のサイズでの性能を保証しません。
