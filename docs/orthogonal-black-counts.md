# 数字セルの色を固定しない隣接黒数

`OrthogonalBlackCounts(orthogonal_counts)` は、各数字を上下左右に隣接する黒マスの個数に合わせます。
[ニコリ公式のペイントエリア](https://www.nikoli.co.jp/ja/puzzles/paint_area/)と同じく、数字マス自体も黒にできます。
数字・部屋は固定入力で、部屋の単色、黒の連結、黒白の2×2禁止は独立した断片で加えます。

## 既存の隣接黒数との違い

| 断片 | 数える場所 | 数字マスの色 |
| --- | --- | --- |
| `OrthogonalBlackCounts` | 上下左右の4マス | この断片では固定しない |
| `AdjacentBlackCounts(diagonal=False)` | 上下左右の4マス | 白にする |
| `AdjacentBlackCounts(diagonal=True)` | 周囲の8マス | 白にする |

数字マス自身、斜め、盤面外は数えません。部屋境界をまたぐ上下左右の黒マスも数えます。
`None` は数字なし、`0` は有効な数字です。1×1の数字0は黒でも白でも通ります。数字1はその盤面では成立しません。
数字の色を固定しないという意味であり、他のルールや追加のセルヒントで色が決まることはあります。

## ペイントエリアの5条件を組み合わせる

[2×3の保存レシピ](../examples/shading-paint-area-recipe.json)は、次の5断片を使います。

```python
from puzzle_defs import (ConnectedBlack, NoBlack2x2, NoWhite2x2,
                         OrthogonalBlackCounts, ShadingRecipe, UniformRooms)

recipe = ShadingRecipe(2, 3, (
    OrthogonalBlackCounts(((2, None, None), (None, None, None))),
    UniformRooms(((0, 0, 1), (0, 1, 1))),
    ConnectedBlack(),
    NoBlack2x2(),
    NoWhite2x2(),
))
```

左上の数字2のセルを含むL字の部屋が黒になり、追加のセルヒントなしで唯一解になります。
数字マスを白にする既存の断片へ置き換えると、この例は矛盾します。
この2×3では黒連結・白の2×2禁止を外しても1解で、その2条件は冗長です。数字を外すと2解、部屋の単色を外すと6解、黒の2×2禁止を外すと2解です。
これはこの固定例の完成集合についての性質で、一般に5条件が互いに同じ意味になるわけではありません。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-paint-area-recipe.json --selection finite --seed 0 --output paint-area.json --quiet
uv run --no-sync python examples/generate_shading.py show paint-area.json
uv run --no-sync python examples/generate_shading.py verify paint-area.json
uv run --no-sync python examples/generate_shading.py check paint-area.json --answer "##./#.."
```

`show` は数字と部屋とルールを表示し、解答テンプレートは `???/???` です。モデルから色が決まっていても、表示時に答えを埋めません。
保存JSONには完全解が含まれます。固定の数字・部屋を自動作成・削減する生成器ではなく、これらを前提に完成解と追加セルヒントを生成します。
追加ヒント数0・既約性は固定数字の最少性や、人間の難易度を保証しません。

## Webと数字の意味の合成

Webで「色を固定せず上下左右の黒数を指定」を選び、`.` を数字なし、0〜4を数字として入力します。
上の例では初期の黒数固定・白連結を外し、部屋の単色・黒連結・両色の2×2禁止を選びます。
部屋配置と数字は既定の2×3の値を使えます。行列のヒントを外してセルヒントだけを選べます。

UI宣言は `orthogonal_counts/clue-grid` と `orthogonal-counts/cell-orthogonal-counts` です。
表示は「接n」で、数字セルを白の固定入力にせず、黒白を入力してサーバーへ解答確認できます。
白固定の「隣n」、白の可視数、白い島、所属成分面積などとは別の配列・型として扱い、同じ入力欄へまとめません。
凡例とアクセシブルな名前にも上下左右の黒数であることを明記します。
端点の丸・白の可視数と同じセルに重ねる場合は、それらの条件がそのセルを白にします。
「接n」は独立した数字として表示し、可視数や解答記号と区別します。

このチャンネルを使う盤面では、複数の数字を別々の枠へ配置します。
他の7種類の数字との各ペア、8種類の数字が同居する例、端点の丸を検証しています。
横幅の長い周囲連続ヒントは1行分を使います。既存の最大8ルールの制限は維持するため、8種類の数字に端点の丸をさらに加える9ルール構成は選べません。
UIが描画できても、複数の数字条件が同時に成立するとは限りません。

## 入力と制約

保存IDは `orthogonal-black-counts`、必須フィールドは `orthogonal_counts` だけです。
数字は `null` または厳密な整数0〜4で、真偽値・小数・文字列・未知/省略フィールドを拒否します。
位置ごとの隣接マス数より大きい数字は、形式上は有効でも求解時に矛盾します。
配列の大きさを盤面へ合わせて検証し、不変に正規化します。同じ断片を重ねる保存問題では数字配列を共有し、異なる配列は拒否します。
古い読込器は新IDを拒否します。ファイルからimportや任意コードを実行しません。

各数字について、4近傍の黒変数の和を数字へ等しくするだけで、新たな補助変数はありません。
回答の射影は黒白セルです。Webの別の盤面型へは暗黙に変換せず、スリザーリンク・セル中心ループのプロファイルは新IDを拒否します。
通常と合成レシピの保存表示に対応し、数字を省略したり色を白に変えたりしません。

独立の有限検査は黒セルとのマンハッタン距離で数え、参照テストは方向ビットマスクの `bit_count` で照合します。
複数の固定数字配列で、1×1・1×2・2×3・3×3の全黒白配置とCSPの完成集合を比べます。
0と数字なし、数字セルの両色、白固定の既存断片との違い、不正な配列・共有の不一致・保存・生成・解答確認も検証します。
全ての数字配列や任意の組合せを網羅した証明ではありません。

保存CLI・黒白Webは最大100セル、Webは最大8ルールです。有限選択・診断は9セルまでです。組み合わせるルールに固有の上限があれば、より小さい方が適用されます。Webは時間予算付きで、通常CLI生成には壁時計の上限はありません。
Webの計算予算を維持し、説明推論は未対応と報告します。求解と一意性検証では適用します。
任意の盤面サイズでの速度・生成成功、人が推測なしで解けることは保証しません。
