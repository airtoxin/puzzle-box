# 各部屋に1つだけ誤った隣接黒数を置く

`OneFalseAdjacentCountPerRoom(rooms, neighbor_counts)` は、各部屋の数字のうち**ちょうど1つだけ**を誤った隣接黒数にします。
[ニコリ公式のウソワン](https://www.nikoli.co.jp/ja/puzzles/usowan/)の条件に対応します。
数字セルは白で、上下左右の黒数が数字と異なる場合だけ「ウソ」です。他の数字は全て正しくなければなりません。
黒の非隣接と白の連結は、この断片に含めず、既存の独立したルールで加えます。

## 数え方と空の扱い

- 数えるのは上下左右の4近傍です。部屋の外の隣接マスも数え、自分自身・斜め・盤面外は数えません。
- `None` は数字なし、`0` は有効な数字です。JSONでは `null`、Webの入力では `.` を使います。
- 「ウソ」は数字の大小ではなく、実際の黒数との不一致です。正しい値より大きくても小さくても構いません。
- 数字が1つだけの部屋では、その数字が必ず誤っています。数字なしの部屋は成立しません。
- 各部屋に1個ずつ要求します。盤面全体で1個という条件ではありません。

既存の隣接黒数の入力形式と共有するため、整数は0〜8を受け付けます。
この断片は常に4近傍なので、5〜8は必ずウソです。角の数字3など、実際の隣接マス数を超える数字も必ずウソになります。
これは入力上の拡張であり、そのような数字を使うことを通常のウソワンの作問手順として推奨するものではありません。

## 3つの断片を組み合わせる

[2×3の保存レシピ](../examples/shading-usowan-recipe.json)は、次の構成です。部屋は盤面全体の1部屋です。

```python
from puzzle_defs import (ConnectedWhite, NonTouchingBlack,
                         OneFalseAdjacentCountPerRoom, ShadingRecipe)

recipe = ShadingRecipe(2, 3, (
    OneFalseAdjacentCountPerRoom(
        rooms=((0, 0, 0), (0, 0, 0)),
        neighbor_counts=((1, None, None), (2, None, None)),
    ),
    NonTouchingBlack(diagonal=False),
    ConnectedWhite(),
))
```

この小盤面では、部屋のウソ数字だけなら8解、黒の非隣接も加えると2解、白の連結も加えると唯一解です。
黒の非隣接を外して白連結だけを加えた場合は4解です。既存の2断片も、この例の一意性に寄与します。
これらの個数は、この配置と数字の有限検査の結果であり、大きい盤面や別の数字に一般化できません。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-usowan-recipe.json --selection finite --seed 0 --output usowan.json --quiet
uv run --no-sync python examples/generate_shading.py show usowan.json
uv run --no-sync python examples/generate_shading.py verify usowan.json
uv run --no-sync python examples/generate_shading.py check usowan.json --answer ".#./..."
```

追加のセルヒントなしで唯一解になり、左上の1は正しく、左下の2がウソです。
`show` は数字・部屋・ルールと `.??/.??` の解答テンプレートを表示し、完全解は表示しません。
保存JSON自体には答えが含まれます。数字と部屋は固定の入力条件で、生成器はこれらを自動作成・削減しません。
ヒント数0・既約性は追加のセルヒントに対する性質で、固定数字の最少性や人間の難易度を保証しません。

## 宣言型UIと組合せ

Webで「各部屋の隣接黒数にウソを1つだけ置く」を選ぶと、既存の部屋入力と周囲の黒数入力を1つずつ表示します。
上の例は、初期の黒数固定を外し、部屋を全て0、数字を `1 . .` / `2 . .` にして、「黒マスを離す」と「白マスをつなぐ」を選びます。
セルヒントだけを有効にできます。行列のヒントを外しても、この例は追加ヒントなしで生成できます。

`rooms/cell-regions`、`neighbor-counts/cell-neighbor-counts`、`answer/binary-cells` の既存の宣言と描画器を再利用します。
数字の表示は「隣n」で、**このルールでは各部屋で1つがウソ**です。表示から正誤やウソの場所を先に明かすことはありません。
数字セルは固定の白で、他のセルを黒白で入力してサーバーへ解答確認できます。ウソの位置は数字と黒白から一意に決まり、別の回答入力にはしません。

他の部屋ルールとは同じ部屋配置、`AdjacentBlackCounts` とは同じ `neighbor_counts` を共有します。
異なる配置・異なる数字を1つの画面や保存問題へ押し込もうとすると拒否します。
同じ数字を4近傍で全て正しくする `AdjacentBlackCounts(diagonal=False)` と同時に要求すると、ウソが必要な条件と矛盾します。
8近傍の正しい黒数は別の条件なので、4近傍ではウソ・8近傍では正しい数字を同時に満たせる場合があります。
UIの適合は成立性の証明ではなく、矛盾なら生成結果は `unsatisfiable` です。

## 保存・制約・検証の範囲

保存IDは `one-false-adjacent-count-per-room` です。必須フィールドは `rooms` と `neighbor_counts` のみで、未知・省略フィールドは拒否します。
部屋は連結した固定の分割、数字は同じ大きさのnullable配列です。真偽値・小数・文字列を数字として受け付けません。
配列を不変に正規化し、既知の型へ明示的に復元します。ファイルからimportや任意コードを実行しません。
古い読込器は新IDを拒否します。黒白以外のWebプロファイルへ暗黙に変換しません。

制約は各数字にウソの真偽変数を作り、`one_of(ウソ, 実際の黒数 == 数字)` で正誤と同値にします。
その変数の和を部屋ごとに1にします。片方向の含意だけで自由にウソを選ぶ実装ではありません。
補助変数は黒白から決まりますが、回答の射影は従来どおり黒白セルだけで、一意性にもその射影を使います。

独立の有限検査は、黒セルとの距離で数えて部屋ごとの不一致を集計します。
参照テストは方向ビットマスクの `bit_count` を使い、1×1・1×3・2×2・2×3・3×3の複数の固定入力で全ての黒白配置とCSPの完成集合を照合します。
0個・2個のウソ、部屋ごとの個数、部屋外の隣接、数字セルの白、数字なしの部屋、共有入力の不一致、保存、生成・解答確認も検証します。
全ての数字配列や部屋分割を列挙した証明ではありません。

この断片自体は部分集合列挙をせず、数字数に比例する局所制約と部屋ごとの和を追加します。
Pythonに専用のセル数上限はなく、保存CLIは既存の25セル、Webと有限選択・診断は9セルまでです。
説明推論の手順は未対応として報告し、唯一解検証では制約を適用します。
Webの計算予算は維持します。任意の大きさ・組合せの生成成功、実行時間、人が推測なしで解けることは保証しません。
