# 解の一意性と条件の組み合わせ

## 「同じ解」の範囲

`p.add(unique())` は、盤面として異なる解が1つだけの場合に `Solution` を返します。
既定では `int_var_grid` / `int_var_map` / `bool_var_map` / `match_var_map` で
作った変数が解を区別します。CP-SAT 内部のループの向き、連結性を示す木、
条件の真偽を表す補助変数は解を区別しません。

パズル定義が補助変数も変数ファクトリから作る場合は、回答に含む変数を指定します。

```python
from puzzle import Puzzle, unique

p = Puzzle("projection")
values = p.int_var_map("value", ["answer", "witness"], 0, 1)
p.set_solution_vars([values["answer"]])
p.add(values["answer"] == 1)
p.add(unique())
assert p.solve() is not None  # witness が 0 / 1 のどちらでも同じ回答
```

Tents はテントの配置を回答とし、木とテントの対応付けは回答に含めません。
汎用のマッチング問題では対応付け自体が回答になるため、`match_var_map` を
一律に除外する仕様にはしていません。ヤジリンではセルの黒白だけでなく辺も回答です。
`result()` の表示が省略した情報まで自動で同一視する機能ではありません。

`set_solution_vars` は渡された iterable を保存し、再度呼ぶと選択を置き換えます。
別の `Puzzle` の変数は拒否します。空の選択では、実行可能なモデルに空の回答が1つあります。
明示選択をしない場合は、`unique()` を追加した後に作った変数も判定対象になります。
`solution_vars` は明示選択のスナップショットをタプルで返し、既定モードでは `None` を返します。
空タプルと `None` は異なります。選択を変更するには引き続き `set_solution_vars` を使います。

## 判定方法と限界

1. 元のモデルを解き、1つの解を得る。
2. モデルを複製し、選択した変数のその組み合わせを禁止する。
3. 複製モデルが **INFEASIBLE** と証明された場合だけ、一意な解として返す。

元のモデルは変更しないため、繰り返しの `solve()` や後からの制約追加も可能です。
補助変数の全組み合わせを列挙しないため、同じ盤面の別の連結証明を数える必要がありません。
ただし一般の求解と同様、別解がないことの証明は重くなり得ます。
タイムアウトや診断結果を扱う公開 API はまだありません。`None` は一意性指定時には
「解なし」「複数解」「一意性を証明できなかった」を区別しません。

## `one_of` の意味

`one_of(a, b, ...)` は **実際に真になる条件がちょうど1つ** であることを要求します。
例えば `one_of(x >= 0, x <= 2)` は `x = 1` を拒否します。
条件の候補を1つ選んで満たせばよい、という意味ではありません。
空の `one_of()` は実行不能、同じ真の条件を2回渡した場合も実行不能です。

線形式の条件についても、指示変数との対応を双方向に制約します。
`!=` のような不連続な範囲も、範囲の補集合を使って否定できます。
背景は [OR-Tools の channeling 説明](https://developers.google.com/optimization/cp/channeling)を参照してください。

`single_cycle` が空の辺集合を許す既存仕様は維持しています。
非空ループを求めるルールでは、別途 `at_least_one(...)` を組み合わせます。
