# 部屋内の成分数と面積を組み合わせる

[ニコリ公式のぬりツイン](https://www.nikoli.co.jp/en/puzzles/nuritwin/)では、各部屋の黒を同じ面積の2成分に分け、部屋境界を越えて黒全体をつなぎます。
この部屋内の2条件を独立した実験的な断片として扱います。
どちらも**Python・ファイル・Webとも盤面全体で9セル以下**です。部屋ごとの上限ではありません。

| 断片 | 意味 |
| --- | --- |
| `RoomComponentCount(rooms, count=2, black=True)` | 各部屋に対象色の上下左右の成分を正確に `count` 個作る。0ならその部屋に対象色なし |
| `EqualRoomComponentSizes(rooms, black=True)` | 同じ部屋内の対象色の各成分の面積をそろえる。0個・1個なら条件を満たす。部屋ごとに面積は変えられる |

両者の `black=False` は白を対象にする変種です。成分数と面積の対象色は独立に選べます。
部屋内での隣接だけで成分を定めます。部屋外の経路で黒がつながっていても、その経路を使って部屋内の成分を合併しません。
斜めの接触は成分をつなぎません。面積を比較する条件は、形や向きの一致を要求しません。

## 個数・連結・面積の区別

1行の同じ部屋で `黒・白・黒` なら黒2成分、`黒・黒・黒` なら黒1成分です。
黒セルの個数を数える `RoomBlackCount` とは異なります。
1つの連結した黒の塊を2つに分割したり、離れた黒をひとまとめにしたりして成分数を合わせることはできません。

面積の条件だけなら、黒がない部屋や1成分だけの部屋も許します。
2成分が1マスと2マスなら、成分数2は満たしますが、面積をそろえる条件には違反します。
ある部屋の成分が全て1マス、別の部屋の成分が全て3マスでも、面積の条件は満たします。

既存の `RoomConnectedBlack(nonempty=True)` は黒の部屋内成分数1に相当します。
`ConnectedBlack` は部屋境界も通った全体の連結で、別条件です。
`ColorComponentSize` も全体の成分の面積を固定するため、部屋内だけの面積条件の代わりにはなりません。

## 小さなぬりツイン型の例

[3×3のレシピ](../examples/shading-nuritwin-recipe.json)は、部屋内の黒2成分・面積一致・黒全体の連結・黒2×2禁止を組み合わせます。
部屋は次の配置です。

```text
0 0 1
0 1 1
1 1 1
```

基礎ルールには2解あり、生成器がセルヒント1個を残して一意にします。
黒全体は1成分ですが、各部屋に制限すると黒2成分になります。
部屋ごとに異なる数字を置く機能は含まず、数字なしの条件にセルヒントを加えた例です。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-nuritwin-recipe.json --selection finite --seed 0 --output nuritwin.json --quiet
uv run --no-sync python examples/generate_shading.py show nuritwin.json
uv run --no-sync python examples/generate_shading.py verify nuritwin.json
uv run --no-sync python examples/generate_shading.py check nuritwin.json --answer ".##/##./..."
```

固定環境の seed 0 では左下の白ヒントが残り、上の解答が通ります。
`show` は部屋とヒントだけを表示し、完全解は出しません。保存JSON自体には答えが含まれます。

```python
from puzzle_defs import (
    ConnectedBlack, EqualRoomComponentSizes, NoBlack2x2, RoomComponentCount, ShadingRecipe,
)

rooms = ((0, 0, 1), (0, 1, 1), (1, 1, 1))
recipe = ShadingRecipe(3, 3, (
    RoomComponentCount(rooms, count=2),
    EqualRoomComponentSizes(rooms),
    ConnectedBlack(),
    NoBlack2x2(),
))
```

部屋を `((0,0,0),(0,1,1),(1,1,1))` にすると、この4条件だけで一意に決まり、追加ヒントは不要です。
一方、成分数を0にして黒全体の非空な連結を残すと矛盾します。
唯一解になること、候補ヒントで識別できること、ルールが互換であることは区別してください。

## UIと入力・保存

Webでは「各部屋の対象色の成分数を固定」「成分の大きさを部屋ごとにそろえる」を選びます。
上の例では初期の黒総数・白連結を外し、黒連結と黒2×2禁止を加え、部屋配置を入力します。セルヒントだけを選べます。
部屋配置の入力・境界表示は既存の `rooms/region-map`・`rooms/cell-regions` を共有します。
成分数は整数、各断片の対象色は独立した真偽値で、新しい描画器・線の入力・成分ラベルの入力は不要です。

保存IDは `room-component-count` と `equal-room-component-sizes` です。どちらも `rooms`・`black`、前者には `count` も必要です。
`count` は0以上・盤面の面積以下の厳密な整数です。真偽値・小数・負数・省略・未知のフィールドは拒否します。
例えば全体が6セルでも、3セルの連結した部屋に3成分を作る指定は満たせません。これは入力範囲内の数学的な矛盾です。
部屋は既存の長方形・連結・整数ラベルの検証に従い、不変の配置へコピーしてラベルを正規化します。
併用する部屋ルールは同じ分割を共有する必要があります。未知IDや他の盤面型は拒否し、データからコードを実行しません。

9セルを超える配置はコンストラクタで拒否します。通常の保存CLIの25セル上限より小さく、表示だけでも読込時に拒否します。
古い読込器は新しいIDを拒否します。新しい読込器でも、上限を超えた配置を黙って簡略化して表示しません。

## 制約と検証

各部屋の非空な連結領域を列挙して、対象色を重複なく覆います。選んだ領域は、同じ部屋の外周で対象色と接しないようにします。
これにより選ばれた領域が実際の部屋内成分となり、成分数は選択領域の個数、面積一致は選択領域の面積の等式で表せます。
境界条件は部屋内だけに課すため、部屋をまたぐ黒の接続を妨げません。
空の部屋では補助の面積変数が複数値を取れますが、領域選択・面積の補助変数は回答に含めず、黒白セルへ射影して一意性を判定します。

独立判定は各部屋で対象色をたどり、参照テストは別の union-find で成分を計算します。
2×3以下の複数配置・両色・成分数0〜3と面積条件について、全回答をDSLと照合します。
3×3では全512配置の独立判定どうしを比較し、実際のぬりツイン型の全解も照合します。
成分の分割・合併、面積不一致、空の補助変数と繰り返した断片、保存・表示・Web解答確認も検証します。

列挙は指数的です。9セルは実装の安全な範囲を絞るための上限で、任意の組合せが一定時間で終わる保証ではありません。
Webの計算予算を維持し、通常CLIには壁時計の打切りがありません。説明推論は両断片を未対応と報告し、唯一解検証では適用します。
唯一解・ヒントの既約性は、最少ヒント数・人間の難易度・大きな盤面の性能を保証しません。部屋の生成・削減も行いません。
