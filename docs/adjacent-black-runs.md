# 周囲8マスの黒い連続区間を指定する

`AdjacentBlackRuns(run_clues)` は、白いヒントマスの周囲8マスを一周したときの、黒い連続区間の長さを指定します。
[GMPuzzles の Tapa 規則と解説](https://www.gmpuzzles.com/blog/tapa-rules-and-info/)を参考にした局所的な断片です。
黒全体の上下左右の連結と、黒い2×2の禁止は含みません。通常の Tapa 型にするには、別に `ConnectedBlack()` と `NoBlack2x2()` を組み合わせます。

## 数字の意味

周囲を北・北東・東・南東・南・南西・西・北西の順で見る、固定8位置の輪です。
北西と北の黒はつながります。白は区切りになり、盤外も白い区切りとして扱います。
端や角で盤外の位置を除いて詰め直すことはありません。例えば角の東と南の黒は、南東も黒でなければ別区間です。
周囲8マスが全て黒なら、長さ8の1区間です。

数字は**順不同の多重集合**です。`1,2` と `2,1` は同じ条件、`1,1` は長さ1の区間が2個ある条件です。
同じ黒成分が輪の外側でつながっていても、局所的に白で区切られた区間は別々に数えます。
これは[隣接黒数](adjacent-black-counts.md)とも、接する[黒成分の面積合計](black-component-sum.md)とも異なります。

| Python | JSON | Web入力 | 意味 |
| --- | --- | --- | --- |
| `None` | `null` | `.` | ヒントなし。この断片はそのセルを白に固定しない |
| `(0,)` | `[0]` | `0` | 白いヒントマス。周囲に黒がない |
| `(1, 2)` | `[1, 2]` | `1,2` | 白いヒントマス。黒の区間は長さ1と2の2個 |

0の扱いは、0を「指定なし」とする可視数や島の面積とは異なります。
数字のない白丸・長さ不明の区間・ワイルドカード・Tapa の派生ルールは扱いません。

## 小さな例を生成して解く

[3×3の固定レシピ](../examples/shading-tapa-recipe.json)は、上中央に `1,2`、中央に `6` を置き、黒連結と黒2×2禁止を組み合わせます。

```text
. 1,2 .
. 6   .
. .   .
```

この3条件には、左右反転したU字の黒配置が2通りあります。セルヒントを1個残すと区別できます。
`1,2` の隣の黒は計3マスですが、輪の外側でつながる黒成分は6マスです。
異なる意味の数字を重ねる場合も、それぞれの条件を別に指定します。

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-tapa-recipe.json --selection finite --seed 0 --output tapa.json --quiet
uv run --no-sync python examples/generate_shading.py show tapa.json
uv run --no-sync python examples/generate_shading.py verify tapa.json
uv run --no-sync python examples/generate_shading.py check tapa.json --answer "#../#.#/###"
```

固定環境の seed 0 では左上の黒ヒントが残り、上の解答が通ります。`show` は完全解を出さず、白い数字マスと残ったセルヒントを表示します。
`?` を埋める解答テンプレートも使えます。保存JSONには答えが含まれます。
数字の位置と値は基礎ルールに固定され、生成・削減されません。削減の対象は別途選んだセル・行・列等のヒントです。
唯一解とヒントの既約性は、数字配置の最小化・最少ヒント数・人間の難易度を保証しません。

```python
from puzzle_defs import AdjacentBlackRuns, ConnectedBlack, NoBlack2x2, ShadingRecipe

recipe = ShadingRecipe(3, 3, (
    AdjacentBlackRuns((
        (None, (1, 2), None),
        (None, (6,), None),
        (None, None, None),
    )),
    ConnectedBlack(),
    NoBlack2x2(),
))
```

## UIと保存契約

Webで「周囲8マスの黒い連続長を指定」を選ぶと、`run_clues/run-clue-grid` 入力と `black-runs/cell-black-runs` 表示を要求します。
空白でセルを、改行で行を区切ります。複数の長さは空白を入れず `1,2`、ヒントなしは `.` です。
上の例では初期の黒数・白連結を外し、この断片・黒連結・黒2×2禁止を選んでください。
`連1,2` 等のラベルと読み上げで他の数字から区別し、0を含むヒントマスは白に固定します。
通常ラベル・可視数・面積・隣接黒数・黒成分合計・部屋・端点の丸とも併用できます。UIの適合は数学的な成立を保証しません。

保存IDは `adjacent-black-runs`、唯一のパラメータは `run_clues` です。JSONは非空の長方形配列で、各セルは `null` または整数配列です。
Pythonではリストも受け取り、並び替えた不変のタプルへコピーします。JSONの各長さ配列も昇順で保存します。
全て `null` なら追加条件はありません。ファイル/UIで同じ表示を共有する複数出現は、並び順の違いを除いて同じ格子が必要です。
未知のフィールド・IDは拒否します。既知の型へ明示的に復元し、データからコードを実行しません。古い読込器は新IDを拒否します。

各ヒントは `[0]` または1〜8の正整数を1〜4個です。複数区間には各1マス以上の白い区切りが必要で、長さの和と区間数の合計が8以下でなければ不正入力です。
`[]`、`[0,1]`、`[1,7]`、真偽値、小数、負数、9以上、凹凸・寸法不一致を拒否します。
一方、角の `[8]` は構文上有効でも、実際の隣接マス数では満たせないため矛盾です。入力エラーと成立しない問題を区別します。

## 実装と範囲

各ヒントについて8位置の256配置から条件を満たすものを選び、盤外が黒になる配置を除きます。
残った配置を既存の和と `one_of` で表します。各候補は周囲の完全な黒白指定なので互いに排他的です。
キャッシュするのは小さな整数マスクだけで、モデルや変数を共有しません。補助変数を除き、回答は黒白セルに射影します。

独立判定では輪上の隣接グラフの成分を数え、テストの参照実装では白で輪を切って連続区間を数えます。
中央3×3と辺・角の小盤面について、全配置の参照結果・有限判定・DSLの回答集合を照合します。
この断片の説明推論は未対応と報告します。唯一解検証には適用しますが、説明できる推論に置き換えません。

保存CLI・黒白Webは最大100セル、Webは最大8ルールです。有限選択・診断は9セルまでです。組み合わせるルールに固有の上限があれば、より小さい方が適用されます。Webは時間予算付きで、通常CLI生成には壁時計の上限はありません。
256配置という局所的な上限が、ルールを重ねたモデル全体の計算時間を保証するわけではありません。
他の盤面型・任意のルールとの合成、より大きい盤面の性能、論理だけでの解きやすさを実証するものではありません。
