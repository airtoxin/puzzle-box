# パズルをまたぐ変数の混在を拒否する

ルールを再利用するときは、変数もそのルールを適用する `Puzzle` から作る必要があります。
以前は別の `Puzzle` の変数を渡しても、CP-SAT 内の変数番号がたまたま同じなら、
受け取り側の別の変数に制約が掛かっていました。

```python
from puzzle import Puzzle, sum_expr

left, right = Puzzle("left"), Puzzle("right")
x = left.int_var_map("x", [0], 0, 1)[0]
y = right.int_var_map("y", [0], 0, 1)[0]

right.add(sum_expr([x]) == 1)
# 変更前: x の条件が right の y に掛かり、y = 1 と解かれる。
# 変更後: ValueError — 同じ Puzzle の変数ではない。
```

名前や変数番号の一致では所属を判別できません。検証には OR-Tools の変数が持つ
モデルの同一性を使います。式を合成する前に調べることで、異なるモデルの同じ番号が
線形式の正規化で1変数にまとめられてしまうことも防ぎます。

## 検査する境界

- `sum_expr`、変数/式同士の比較、`|` は、異なるモデルの変数が混じると `ValueError`。
- `Puzzle.add` は、渡された条件が受け取り側のモデルに所属するかを検査。
- `one_of` と複合制約は、全要素を検査してからモデルへ追加。
- 全異・連結・単一ループ・形状関係・境界交差の各制約も同じ検査を適用。
- マッチングと選択変数を結ぶ `right_selected_iff` も、検査される式経由で構築。

同じモデル内の通常の操作、同じ制約の再追加、空の合計のような定数は引き続き使えます。
エラーで拒否された `add` は、所属チェック前の状態から対象モデルを変更しません。
ただし、呼び出し引数を作るためにすでに評価された `x == 1` などの式は、
その式を作ったモデルに補助変数を追加している場合があります。
引数評価も含む汎用トランザクションを実装したものではありません。

## 検証と範囲

回帰テストは両モデルの先頭変数を使い、意図的に内部番号が衝突する状況を作ります。
異なるモデルの値が偶然同じかどうかではなく、モデルそのものの同一性で拒否すること、
拒否後に受け取り側のモデルが変わらないことを確認します。
各制約の入口、変数と線形式が混在する比較、否定条件や入れ子の合計も対象です。

この変更は公開 DSL の通常の式構築と制約追加に対する入力検証です。
`_internal` を直接組み合わせてから包み直すなど、CP-SAT の生の式を介した操作は
検証の対象として保証しません。失われた所属情報を後から復元することはできません。
`Solution.value` に別モデルの変数を渡す誤用、グリッドの形、重複キー、
マッチング候補の重複や未宣言の端点を含む入力の検証は別の改善課題です。
大きな式に対する検査の計算量のベンチマークも今回の対象外です。

既存の一意性判定・ルール修正・生成器改善には依存せず、`main` に対する独立した変更です。
