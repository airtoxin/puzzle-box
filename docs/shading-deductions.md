# 唯一解と、説明できる手順で解けることを分ける

`examples/explain_shading.py` は保存された黒白問題に対して、限定した局所推論と白連結の推論を順番に説明します。
唯一解があることは事前に検証しますが、**ソルバーの答えを推論の手順として表示しません**。
実装した手順で進めなくなった場合は、未知のマスを `?` のまま残して「未解決」と表示します。

これは説明可能な手順の小さな実験です。完了しても、人間が容易に気付けること、難易度や
面白さを保証しません。未解決でも、人間には解けない問題だという意味ではありません。

## 完了する例と、唯一解でも止まる例

リポジトリのルートで `uv sync --all-packages --group dev --locked` を実行してから使います。
このコマンドは推論によって分かった答えを表示します。自分で解く場合は先に
[問題の表示・解答確認](play-shading.md)を使ってください。

```sh
uv run --no-sync python examples/explain_shading.py examples/shading-deduction-solved.json
uv run --no-sync python examples/explain_shading.py examples/shading-deduction-stalled.json
```

[完了する例](../examples/shading-deduction-solved.json)は2×2、黒２個、黒の縦横隣接禁止で、右下が黒と分かっています。
座標は０始まりです。

1. `(1,1)` が黒なので、隣の `(0,1)` は白。
2. 同じ黒マスの隣の `(1,0)` も白。
3. 黒２個の指定に対して既知の黒は１個、未知は `(0,0)` だけなので、ここが黒。

出力の最終状態は `#./.#`、状態は `solved`、終了コードは0です。
手順ごとに参照したルールまたはヒントの番号、対象マス、前提となる既知のマスを表示します。
各前提が直接のヒントか、過去の何番の手順で分かったかも追えます。

[止まる例](../examples/shading-deduction-stalled.json)は3×3、黒３個、黒の縦横隣接禁止で、
２行目が黒１個、２列目が黒０個、３列目が黒２個というヒントがあります。
独立な検証では唯一解ですが、ここで実装した個数の飽和と隣接の手順では２列目を白にしたところで止まります。

```text
State: ?.?/?.?/?.?
Unresolved: 6 cells. The supported deductions are exhausted; no guesses were made.
```

この例の状態は `stalled`、終了コードは1です。**対象ルール型がすべて対応済みでも、推論法は不完全**です。
ここから場合分けをしたり、３列目の可能な配置を数えたりする手順は実装していません。
保存された正解を使って残りを埋めることもしません。

同梱の問題データを固定した再現例なので、生成環境の seed に依存せず試せます。
新しく生成した問題には、同じ形式で `explain_shading.py puzzle.json` を実行できます。

## 実装した推論

| 手順 | 対象 | 使う条件と結論 |
|---|---|---|
| `count-satisfied` | 黒個数ルール、行・列ヒント | 必要な黒が既にそろったら、対象範囲の残りは白 |
| `count-fill` | 同上 | 既知の黒数＋未知マス数＝指定個数なら、未知マスはすべて黒 |
| `black-neighbor` | 黒隣接禁止 | 禁止された隣接組の片方が黒なら、他方は白。対角禁止の設定も尊重 |
| `last-in-window` | 白だけの2×2禁止 | 2×2内の３マスが白で最後の１マスが未知なら、そのマスは黒 |
| `white-connector` | 白連結 | 未知の１マスを除くと既知の白マス２つをつなぐ経路がなくなるなら、そのマスは白 |

セルの直接ヒントは初期値であり、推論の手順数には含めません。白連結の推論は必須通過マスだけで、
既知の白マスが２つ以上必要です。例えば白連結・非空だけで１マスが白になる問題は依然として未解決です。
`rules_without_deductions` は推論が全くないルール番号（1始まり）を示し、既定4型では空です。
[追加6断片](shading-fragments.md)、[部屋・行列・ピースの6断片](room-fragments.md)、[成分の形の2断片](component-shapes.md)、[固定数字](number-fragments.md)、[連続長上限](run-length.md)、[固定成分サイズ](component-size.md)、[白の可視数](white-visibility.md)、[外枠への接続](component-border.md)、[白い島の面積](white-island-areas.md)、[隣接黒数](adjacent-black-counts.md)、[黒成分の面積合計](black-component-sum.md)、[セルの道の2断片](cell-path-fragments.md)、[部屋の単色と輪なしの2断片](room-uniform-forest.md)、[8近傍の連結](corner-connected-color.md)、[数字なし白成分を許す面積](white-area-clues.md)、[白の端点の丸](white-endpoint-markers.md)、[周囲の黒い連続区間](adjacent-black-runs.md)、[部屋の水位](room-fill-levels.md)、[部屋間の2断片](room-neighbors.md)、[部屋内成分の2断片](room-components.md)には推論手順がなく、この配列に番号を記録します。
それらも事前の唯一解検証では適用しますが、手順の生成では使いません。
対応済みのルール・ヒントだけで確定できないマスは未解決のままです。
空であっても、そのルール型に関する全推論を網羅したことにはなりません。

局所推論をレシピのルール順、ヒント順、各範囲の座標順で走査し、使える局所推論がないときに
白連結をルール順・未知マスの座標順で調べます。１マス確定するごとに局所推論の先頭から
見直し、どの手順も使えなくなったら終了します。未知マスは単調に減り、推論は最大で盤面のマス数回です。
手順の短さや、人間にとって自然な提示順を最適化してはいません。

## 白をつなぐために必須のマス

```sh
uv run --no-sync python examples/explain_shading.py examples/shading-connector-sample.json
uv run --no-sync python examples/explain_shading.py examples/shading-connector-sample.json --json
```

[同梱例](../examples/shading-connector-sample.json)の初期状態は `.??/##.` です。
左上 `(0,0)` と右下 `(1,2)` は白、左下２マスは黒と分かっています。
未知の `(0,1)` を黒とすると、左上から他の白へ進めません。したがって `(0,1)` は白です。
次に `(0,2)` を黒とすると、今度は右下の白につながらないため、ここも白です。
２つの推論で `.../##.` まで確定します。

判定に使うグラフは、**既知の黒だけを除き、未知マスもすべて白として通れる**縦横の隣接グラフです。
この最も経路の多い状態でも候補マスを除いたら既知の白２つが分断されるなら、未知マスをどのように
黒白に決めても、その候補が黒である解はありません。候補を白と確定できます。
一般の盤面仮定やソルバー探索による推測ではなく、白連結の必要条件をグラフで確認する手順です。

各手順の `connectivity_witness` は、分断される既知の白２マスを `terminals`、
候補を除いた後に一方から到達できる全マスを `reachable_without_cell` として記録します。
対象マスと既知の黒を除いたグラフを再構成すれば、領域にもう一方の白が含まれないことを再検証できます。
白マスが１つ以下の場合や代替経路がある場合は、この手順で確定しません。
白がない孤立領域の黒化、非空条件だけによる確定などは実装していません。

## 検証と説明を分離する

入力は既存の `shading-v1` / `shading-v2` 問題です。既存の入力検証と生成物の検証を使い、
唯一解・保存解との一致・ヒントの既約性を先に確かめます。矛盾・複数解・改変された保存解・
削除可能なヒントを含む入力はエラーです。任意の途中盤面や冗長なヒントを含む手作り問題の入力機能ではありません。

推論関数に渡すのはルールとヒントだけです。保存解やソルバーを参照せず、各結論を導きます。
最後に既知となったマスが検証済みの解と一致するか照合し、不一致ならエラーにします。
照合によってマスを修正したり、未解決のマスを補完したりはしません。

自動テストでは、各手順の対象範囲が実際の引用元と一致し、前提が既出であることを確認します。
さらに、**引用した１つの制約と表示した前提だけ**を満たす全割当を独立に列挙し、結論が共通することを確かめます。
唯一解全体と一致するだけのテストでは、正解を読んだ推測も通ってしまうためです。
局所推論は2×2の実現可能な部分盤面、行列ヒント、対角隣接、2×2窓と照合します。
連結推論は1×3・3×1・2×2・2×3・3×2の全ての実現可能な部分盤面で、
白連結だけを満たす全完成割当と照合し、別方式の推移閉包でも分断領域を検証します。
同梱例のDSL全解、3×3で推論が進んでも未解決のまま残る例も確認します。

## 出力と範囲

```sh
uv run --no-sync python examples/explain_shading.py examples/shading-deduction-stalled.json --json
```

JSONには `status`、`givens`、`steps`、`cells`、`unresolved_cells`、未実装ルール番号と検証結果を出します。
未知マスは `null` で、保存された完全な正解を別フィールドに含めません。
ステップには引用元、範囲、前提の由来、適用手順、理由、結論を記録します。
連結推論のステップには上記の分断根拠も追加します。ルール・ヒント・手順番号は１始まりです。
入力ファイルへの書き込みはありません。

| 終了コード | 意味 |
|---:|---|
| 0 | 対応する手順ですべて確定した |
| 1 | 問題の唯一解は確認済みだが、この手順では未解決 |
| 2 | 入力や保存問題の検証に失敗した |
| 3 | 検証後の推論矛盾、保存解との不一致などの内部エラー |

推論手順を持つのは既定４ルールです。入力には追加35断片も使えますが、その手順は未対応と報告します。
正確な組み込み型、９セル、８ルール出現、32ヒント出現までです。JSONは64 KiB以下です。
白連結は必須通過マスだけが対象です。一般の背理法、場合分け、仮定探索、任意DSL、ループとの異種合成は説明しません。
連結判定は各未知マスを１つ除いたグラフの到達可能性を調べます。全処理の上限を定めるものではありません。
事前のソルバー検証は局所推論とは別の処理で、全処理の時間上限はありません。
