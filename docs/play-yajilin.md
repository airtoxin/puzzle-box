# 黒マスとループの両方を入力して確認する

`generate_yajilin.py check` は、完成した黒白配置とループ辺を一緒に確認します。
対象は[ヤジリン生成レシピ](yajilin-composition.md)で保存した `yajilin-v1` の問題です。
固定の矢印マスに加え、数字・黒白指定・辺指定のヒントを扱います。

## 答えを見ずに始める

リポジトリのルートで実行します。

```sh
uv sync --all-packages --group dev --locked
uv run --no-sync python examples/generate_yajilin.py generate --seed 6 --output coupled.json --quiet
uv run --no-sync python examples/generate_yajilin.py show coupled.json
```

`--quiet` は答えを含むJSONの画面出力を抑え、`show` はヒントだけを表示します。
保存JSON自体には答えが含まれます。解を図で見るときだけ `show FILE --solution` を使います。

普通セルの記号は黒白入力に合わせて、`#` が黒、`.` がループ上の白です。
未確定セルは辺の `?` と見分けられるよう図では `[?]` と表示します。
矢印の `>?` などは数字ヒントのない固定マスで、未確定の普通セルではありません。

[付属例題](../examples/yajilin-sample.json)の入力用テンプレートは次の2つです。

```text
Cells template: ????/@???/????
Edges template: ???/0???/0??/0??1/???
```

テンプレートに含むのは明示的な黒白・辺のヒントと、固定矢印の構造だけです。
数字から推論できる黒マスや線を、自動で埋めることはありません。

## 黒白と線を入力する

`check FILE --cells "セルの各行" --edges "辺の各段"` に、完成した2つの入力を渡します。
どちらも `/` 区切りで、読みやすさのための空白は入れられます。

| 入力 | 記号と並び順 |
| --- | --- |
| `--cells` | 上からセルを1行ずつ、各行は左から右へ。`#` は黒、`.` は白、`@` は固定矢印マス。 |
| `--edges` | 図の上から横辺の段・縦辺の段を交互に、各段は左から右へ。`1` は使う辺、`0` は使わない辺。 |

セル側の `?` を `#` または `.` に置き換え、矢印の `@` はその位置に残します。
矢印の方向や数字は問題で固定されているので、入力し直しません。
線側の `?` は `0` または `1` に置き換えます。矢印に接する辺は構造上使えないため、テンプレートでは0です。

R行×C列なら、セルはR行・各C文字です。線は **2R−1段**で、C−1文字の横辺とC文字の縦辺が交互になります。
3×4の例では横辺3文字・縦辺4文字・横辺3文字・縦辺4文字・横辺3文字です。
辺がセルの**中心**を結ぶため、[Slitherlink](play-slitherlink.md)のマス外周用の入力とは寸法が異なります。
形式はどちらも0/1の辺の段ですが、図の座標と寸法に合わせて入力してください。

<details>
<summary>付属例題の完成入力（答えを含みます）</summary>

```sh
uv run --no-sync python examples/generate_yajilin.py check examples/yajilin-sample.json --cells "#..#/@.../#..." --edges "010/0110/001/0101/011"
```

この例題では黒マス3個・ループ8辺です。別の生成問題にこの答えを流用できるとは限りません。

</details>

| 状況 | 終了コード | 結果 |
| --- | --- | --- |
| 黒白・線の両方が正解 | 0 | `Correct. All rules and clues are satisfied.` |
| 形式は正しいが片方でも不正解 | 1 | `Not correct. Check the rules and given clues.` |
| 入力の不足・未完成・不正な文字や寸法・矢印位置違い・不正な保存問題 | 2 | 標準エラーに理由を表示 |

既知のヒントに反する黒白、矢印や黒マスへ入る線、枝分かれ、空の線集合なども、
文字と寸法が正しければ不正解です。正誤確認は答えや間違った位置を表示せず、保存ファイルも変更しません。

## 両方を検証する理由と範囲

黒マスだけを正解にしても、ループが一意に決まるとは限りません。
矢印なし3×4の全白配置には2種類のループがあるため、片方の入力だけでの確認は受け付けません。
黒白と辺の両方を回答として扱う既存の求解契約を使います。

保存した答えもそのまま信用しません。既存の `verify` で唯一解・保存解との一致・各ヒントの必要性を確認してから比較します。
改変された答え、曖昧な問題、余分なヒントがある問題は生成物の契約に従って入力エラーです。
`verify` は保存問題の検証、`check` は人が入力した完成解の正誤確認です。

テストでは独立した次数・到達可能性・黒白との接続・ヒント判定を使い、3×4の40ループや
2×2の全256通りの黒白＋辺入力と照合します。同じ黒白を持つ異なるループ、保存解の改変、
数字を消した矢印、生成から表示・解答確認までのCLI操作も確認します。

12セル以下の既存形式が対象です。規則を外した実験形式 `coupled-puzzle-v1`、途中解答の矛盾判定、
次の一手、手筋説明、描画GUIは扱いません。確認のたびに求解するため、処理全体の時間上限はありません。
