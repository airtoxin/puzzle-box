# 生成したループを解いて確認する

`generate_slitherlink.py` は、保存した問題の表示と、完成したループの正誤確認に対応します。
黒白のマスを入力する方式とは異なり、**全ての辺の使用・不使用**を入力します。
数字ヒント・辺ヒント・任意の長さ指定を含む `slitherlink-v1` が対象です。

## 表示して解く

リポジトリのルートで依存環境を準備してから実行します。

```sh
uv sync --all-packages --group dev --locked
uv run --no-sync python examples/generate_slitherlink.py generate --rows 2 --cols 2 --loop-length 8 --seed 2 --output loop.json --quiet
uv run --no-sync python examples/generate_slitherlink.py show loop.json
```

`--quiet` は保存時の答えを含むJSONの画面出力を抑えます。保存ファイル自体には答えがあります。
`show` はヒントと入力用テンプレートだけを表示します。例えば[付属の例題](../examples/slitherlink-sample.json)では、
右下の外周辺だけが使用指定なので、テンプレートは次のようになります。

```text
Answer template: ??/???/??/??1/??
```

図の上から順に、横向きの辺の段と縦向きの辺の段を交互に読みます。
各段は左から右へ並べ、`/` で区切ります。マスの数字や頂点の `+` は入力しません。

| 2×2の入力の段 | 辺の位置 | 文字数 |
| --- | --- | --- |
| 1 | 一番上の横辺 | 2 |
| 2 | 上段のマスに接する縦辺 | 3 |
| 3 | 中央の横辺 | 2 |
| 4 | 下段のマスに接する縦辺 | 3 |
| 5 | 一番下の横辺 | 2 |

`?` を使う辺は `1`、使わない辺は `0` に置き換えます。既知の辺ヒントはあらかじめ `1` / `0` で表示します。
数字から推論できる辺でも、辺ヒントそのものではなければテンプレートでは `?` のままです。
R行×C列なら、全体は `2R+1` 段で、C文字の横辺段とC+1文字の縦辺段が交互になります。
空白は読みやすさのために入れられますが、段の区切りには `/` が必要です。

## 完成した辺を確認する

`check FILE --answer "完成したテンプレート"` で確認します。全ての辺を `0` または `1` にしてください。
`?` を残した途中解答は不正解とは区別し、入力エラーにします。

<details>
<summary>付属例題の完成解と確認コマンド（答えを含みます）</summary>

```sh
uv run --no-sync python examples/generate_slitherlink.py check examples/slitherlink-sample.json --answer "01/011/10/101/11"
```

この入力は、長さ8・右上の数字3・右下の使用辺を満たすループです。
生成した別の問題にこの答えを流用できるとは限りません。

</details>

| 状況 | 終了コード | 出力 |
| --- | --- | --- |
| 正解 | 0 | `Correct. All rules and clues are satisfied.` |
| 形式は正しいが不正解 | 1 | `Not correct. Check the rules and given clues.` |
| 途中解答・文字数違い・不正な文字・不正な保存問題 | 2 | 標準エラーに理由を表示 |

全辺0、枝分かれ、複数ループ、ヒント違反などは、入力形式が正しければ不正解です。
正誤確認は答えや間違った辺の位置を表示しません。保存ファイルも変更しません。
解を図で見るときだけ、明示的に `show FILE --solution` を使います。

## 検証と範囲

保存された解をそのまま信用せず、既存の `verify` でヒントの唯一解・保存解との一致・各ヒントの必要性を確認してから比較します。
そのため、曖昧な問題や改変された答えを入力に渡しても、誤った「正解」は返しません。
ヒントが余分な問題も、生成物の既約性の契約に従って入力エラーになります。
`verify FILE` は生成物の検証、`check FILE --answer ...` は人が入力した完成解の確認です。

2×2の全4,096辺配置を入力座標と照合し、独立した次数・到達可能性の検査で得た13ループ、
枝分かれや辺欠落などをルール・ヒントの検査と比較します。1×1の0ヒント問題、縦長・横長盤面、
ヒントだけの表示、不正入力、保存答えの改変、実際のCLIでの生成から解答確認までをテストします。

CLIの9マス上限は維持します。確認のたびに求解するため、経過時間の上限は保証しません。
途中解答の矛盾判定、手筋の説明、次の一手、描画GUIには対応しません。
ヤジリンは別の[黒白＋辺の解答確認](play-yajilin.md)を使います。辺の座標の意味と入力寸法も異なります。
保存形式・生成アルゴリズム・唯一性の意味は[ループのレシピ](slitherlink-composition.md)を参照してください。
