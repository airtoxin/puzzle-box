# 数字のない白成分も許す面積ヒント

`WhiteAreaClues(areas)` は、各白連結成分に数字が0個か1個入ることを要求します。
数字マスは白で、その成分の面積を数字と等しくします。数字なしの白成分も許します。
成分は上下左右でつながり、形・黒の連結・角経由の接続・黒2×2禁止は別の条件です。

[モチコロの公式ルール](https://www.nikoli.co.jp/ja/puzzles/mochikoro/)の、数字が0個か1個という条件を切り出した断片です。
長方形成分・8近傍連結・黒2×2禁止と組み合わせられます。数字の配置を生成器が選択・削減する機能ではありません。

## ぬりかべの島のルールとの違い

| ルール | 白成分ごとの数字数 | 数字がある場合 | 格子が全て0の場合 |
| --- | --- | --- | --- |
| `WhiteAreaClues(areas)` | 0個または1個 | 面積を指定する | 黒白を何も制限しない |
| `WhiteIslandAreas(areas)` | 必ず1個 | 面積を指定する | すべて黒になる |

両方とも0は数字なし、正の整数は白い数字マスです。`null` は受け付けません。
数字なしのマス自体を白に固定する意味ではありません。同じ値の数字も2つ同じ白成分に入れることはできません。

```python
from puzzle_defs import ShadingRecipe, WhiteAreaClues

recipe = ShadingRecipe(2, 2, (WhiteAreaClues(((1, 0), (0, 0))),))
```

左上は面積1の白成分です。右下は黒でも、別の数字なし白成分でもかまいません。
`WhiteIslandAreas` に置き換えると右下も黒にする必要があります。既存のその意味は変更していません。
両方を同じ格子で選べば、強い方の「数字が必ず1個」も適用されます。

## 数字なし長方形を含む問題を生成する

```sh
uv run --no-sync python examples/generate_shading.py generate --recipe examples/shading-mochikoro-recipe.json --selection finite --seed 0 --output mochikoro.json --quiet
uv run --no-sync python examples/generate_shading.py show mochikoro.json
uv run --no-sync python examples/generate_shading.py verify mochikoro.json
```

[2×3の例](../examples/shading-mochikoro-recipe.json)は左上に1、残りに数字なしの0を指定します。
白の長方形成分・辺と角の連結・黒2×2禁止に、追加の組合せ条件として黒3個を指定します。
黒3個は通常のモチコロの規則には含まれません。
ルールだけでは2解があり、生成器は区別に必要なセルヒントを1つ残します。
どちらの答えにも数字なしの白成分があり、`WhiteIslandAreas` への置換では解なしになります。
固定数字の位置・値はレシピの一部で、削減するセルヒントとは区別します。
`show` のテンプレートを黒 `#`・白 `.` で埋め、`check mochikoro.json --answer "行/行"` に渡すと確認できます。
完全解は画面で隠しますが、保存JSONには答えが入っています。

## UIと保存形式

Webでは「数字がある白成分の面積を固定」を選びます。
`areas/number-grid` と `island-areas/cell-island-areas` は既存の島の面積と共有し、正の数字を白いマスに四角で囲んで表示します。
数字の意味は両ルールとも面積であり、違いは数字がない成分を許すかどうかです。
両方を選んだときも入力欄は同じ格子1つを使い、違う格子を同じ表示へ黙って重ねません。
固定ラベル・可視数・隣接黒数などの別の意味の数字とは、引き続き別の格子です。
既存の描画器と入力だけを使い、線入力や新しいチャンネルは追加しません。

保存IDは `white-area-clues`、フィールドは `areas` だけです。
盤面と同寸の長方形配列と厳密な整数0〜99を要求します。JSONは配列の配列に限り、空・不揃い・真偽値・小数・`null`・未知フィールドを拒否します。
実現可能な面積を超える値は有効な入力ですが、解なしになる場合があります。
Python側では不変の格子へコピーし、保存は正確な組み込み型に限定します。データからコードを実行しません。
新IDを知らない旧版の読み手は拒否します。既存 `white-island-areas` の意味と形式はそのままです。

## 実装・範囲・検証

既存の島の面積と、白成分候補の列挙・被覆・境界の制約を共有します。
従来ルールは数字1個と面積が一致する候補だけを使い、新ルールは数字0個の候補も加えます。
各白マスは1候補に属し、選ばれた候補の外に白が接しないため、1成分を分割して数字数をごまかすことはできません。
数字が全くない新ルールでは何も制限せず、候補列挙もしません。補助変数は `ShadingRecipe` の見える回答に含めません。
Python・保存・Webとも9セル以下です。コンストラクターで上限を確認し、列挙前に拒否します。
Webは既存の計算予算を使い、通常CLIには壁時計の上限がありません。

有限検査器は白成分全体の数字数と面積を調べます。別のテスト参照実装は各数字から白をたどり、面積と他の数字の混入を調べます。
数字なしの成分、数字2個の禁止、全0格子、新旧ルールの差、保存・表示・解答確認を検証します。
DSLの全回答比較は小盤面に限定し、3×3では中央が面積1の小さな回答集合も調べます。任意サイズの性能を保証するものではありません。
説明可能な推論手順は未対応で、未対応ルール番号として報告します。一意性と人間の解きやすさは別の性質です。
